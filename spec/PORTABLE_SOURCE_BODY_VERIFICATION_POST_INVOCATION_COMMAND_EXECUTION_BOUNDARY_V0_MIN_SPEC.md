## 4. Definitions

`post_invocation_command_execution_boundary` means a boundary over an already recorded command invocation basis. It may record that the invocation basis is preserved for one future command execution step. It does not execute the command.

`recorded_command_invocation_basis` means the clean command invocation result and terminal-summary basis recording one bounded command invocation event, one-shot authorization token spend exactly once, authorization token reuse blocked, command execution still not performed, command output/result/success still not created, consumed request token still closed, v1 predecessor failure preserved, and returned-result containment preserved.

`future_command_execution_step` means a later, separately bounded step that may address actual command execution. This specification does not perform that step and does not schedule, approve, or authorize that step.

`spent_one_shot_authorization_token` means the one-shot command invocation authorization token has already been spent exactly once by the recorded command invocation event. It must not be revived, reused, respawned, discharged again, or treated as reusable permission.

`authorization_token_reuse_blocked` means no second use, repeat use, standing use, durable lane, replay, re-consumption, token revival, token respawn, or token reuse posture may be created from the spent one-shot authorization token.

`command_execution` means the actual live execution event of the command. Post-invocation command execution boundary is not command execution.

`command_output` means output emitted by separately bounded command execution. Post-invocation command execution boundary creates no command output.

`command_result` means a result object produced by separately bounded command execution. Post-invocation command execution boundary creates no command result.

`command_success` means successful command execution, successful return, exit status, passed execution check set, or comparable success posture from a later live run. Post-invocation command execution boundary creates no command success.

`execution_permission` means permission to execute the command. Post-invocation command execution boundary is not execution permission.

`execution_approval` means approval that command execution may be performed. Post-invocation command execution boundary is not execution approval.

`standing_execution_lane` means any durable or reusable posture that would allow command execution without a separately bounded step. Post-invocation command execution boundary must not create a standing execution lane.

`repeat_execution_permission` means any permission to execute more than once, reuse the invocation basis as reusable execution permission, or treat one execution boundary as a durable execution lane. Post-invocation command execution boundary must not create repeat execution permission.

`standing_invocation_lane` means any durable or reusable posture that would allow command invocation without a separately bounded step. Post-invocation command execution boundary must not create a standing invocation lane.

`repeat_invocation_permission` means any permission to invoke more than once, reuse the consumed request, reuse the spent command invocation authorization token, or treat the recorded invocation event as reusable command permission. Post-invocation command execution boundary must not create repeat invocation permission.

`consumed_request_token_closed` means the consumed request token remains closed after one clean request consumption. It must not be reopened by boundary, invocation, execution, output, result, success, narration, path posture, artifact existence, later carrier possession, or spent token posture.

`execution_boundary_non_claim` means an explicit false posture preserving that post-invocation command execution boundary is not command execution, command output, command result, command success, execution permission, execution approval, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

Command execution, command output, command result, and command success remain separately bounded future work.

## 21. Closing Boundary Statement

Portable source-body verification post-invocation command execution boundary may record that one recorded command invocation basis is preserved for one future command execution step. It preserves that command execution is not performed, command output, command result, and command success do not exist, execution permission is not created, execution approval is not created, no standing execution lane or repeat execution permission is created, authorization token reuse remains blocked, the consumed request token remains closed, v1 predecessor failure remains visible, v2 successor containment is preserved, and any actual command execution, command output, command result, or command success still requires a separate bounded step. It does not authorize command output, command result, command success, deployment, runtime hosting, public release, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.
