# Receiver-Side Answerable Basis Candidate Evaluation Basis Preparation Request Declaration V0 Minimum Specification

## 1. Purpose

This specification defines the shape and non-claims of one future bounded source-body preparation request for one separately prepared receiver-side answerable-basis candidate evaluation-basis declaration. The request is source-body-originating only. It may ask one explicitly referenced preparer to prepare one declaration for the exact selected candidate under the governing declaration specification. It does not issue a live request, select a preparer, admit a role, assign authority, create an obligation, prepare or supply a declaration, validate a declaration, invoke an operation, derive a result, or authorize downstream work.

## 2. Scope

The request is limited to one selected candidate, one selected declaration family, one explicitly referenced intended preparer, and one optional future declaration response. It creates no resolver, test, artifact, terminal summary, live request, preparer reference, role admission, evaluator authority or identity, populated declaration, dimension-basis record, evaluation invocation, candidate evaluation, result, sufficiency, attestation, receipt, presence re-evaluation, identity, relation, coupling, FIELD machinery, runtime, API, public intake, authority, standing, or follow-on authorization.

## 3. Request Question

Given that the declaration implementation line recorded `REQUIRES_DECLARATION_MATERIAL` and no live declaration, preparer reference, origin reference, source-body-authorship posture, or dimension record exists, may one future bounded source-body request ask exactly one explicitly referenced preparer to prepare exactly one evaluation-basis declaration for the selected candidate without converting the request into role admission, obligation, authority, standing, declaration existence, evaluation basis, operation admission, or candidate evaluation?

## 4. Required Answer

Yes, but only as one separately bounded preparation-request declaration. A future request may identify one intended preparer by declared reference only; describe the response shape governed by `spec/RECEIVER_SIDE_ANSWERABLE_BASIS_CANDIDATE_EVALUATION_BASIS_DECLARATION_V0_MIN_SPEC.md`; and request one separately prepared declaration only. Response remains optional. The request creates no duty, deadline, debt, scheduled retry, preparer-role admission, evaluator authority, or reusable request route.

## 8. Future Request Shape

A future request may contain only request identifiers; exact selected candidate and declaration identifiers; intended preparer reference; intended preparer-role, relation-to-candidate, relation-to-source-body, and custody-posture declarations; request-origin reference; request timestamp as declaration only; required response declaration reference; response-shape requirements; eight required dimension identifiers; request statement; request non-meaning; request non-claims; optional-response posture; and single-request exhaustion posture.

## 9. Eight-Dimension Response Scope

The request may ask for exactly one declaration containing exactly these records:

1. `candidate_structural_correspondence`
2. `declared_provenance_posture`
3. `receiver_authorship_posture`
4. `separate_custody_posture`
5. `refusability_posture`
6. `could_have_been_withheld_posture`
7. `prior_knock_correspondence_posture`
8. `capture_record_posture`

It asks for bounded basis and rule-input postures only. It must not ask the preparer to select `SATISFIED`, `NOT_SATISFIED`, or `INDETERMINATE`, or to decide candidate sufficiency, attestation, receipt, presence, authority, standing, or downstream results. The existing evaluation-operation resolver alone may later derive dimension results after separate validation, supply, and admission.

## 13. Occurrence, Trace, and Reception Separation

Declaration submission is separate from preparation; declaration validation is separate from submission; operation supply is separate from declaration validation; operation admission is separate from supply; and candidate evaluation is separate from admission. No later occurrence is created here.
