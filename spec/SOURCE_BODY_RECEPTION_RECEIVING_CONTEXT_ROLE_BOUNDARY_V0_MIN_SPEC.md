## 4. Definitions

`source_body_reception_receiving_context_role_boundary` means a bounded review surface that records what the declared receiving context may be called for one declared reception request after source-body reception identity preservation. It is role boundary only and is not reception recognition, reception authorization, source receipt, source authority, receiving-context governance, or operation permission.

`selected_identity_preservation_result` means one source-body reception identity preservation result whose outcome is `SOURCE_BODY_RECEPTION_IDENTITY_PRESERVED` and whose failed check count is zero.

`receiving_context` means the declared context from the source-body reception request. It remains context only. It is not source, authority, current, receiver, adopter, validator, invalidator, operator, vessel, derivative, permission, governance, publication flow, or follow-on authority.

`receiving_context_role` means the bounded label and limits assigned to the receiving context for this declared request. A role is a review posture only. It is not permission.

`request_declaration_context_role` means a role in which the receiving context is named only as the context that declared or carries the request for later review. It does not recognize reception, authorize reception, receive source, validate source, or replace source.

`reference_review_context_role` means a role in which the receiving context may frame later review of a selected source-body surface as reference context only. It does not make the receiving context source, authority, current, validator, receiver, adopter, vessel, derivative, or operator.

`inspection_review_context_role` means a role in which the receiving context may frame later bounded inspection of a selected source-body surface only. It does not create operation permission, source validation, source invalidation, source receipt, adoption, authority, currentness, standing, or publication flow.

`carrier_context_review_role` means a role in which the receiving context may frame later review in relation to carrier context only. It does not create carrier currentness, carrier authority, vessel relation, derivative relation, operation permission, source replacement, source receipt, or publication flow.

`unsupported_receiver_role` means any role that treats the receiving context as receiving source. It is blocked by this boundary.

`unsupported_adopter_role` means any role that treats the receiving context as adopting source. It is blocked by this boundary.

`unsupported_validator_role` means any role that treats the receiving context as validating or invalidating source. It is blocked by this boundary.

`unsupported_authority_role` means any role that treats the receiving context as source authority, receiving authority, governance authority, carrier authority, current authority, or operation authority. It is blocked by this boundary.

`unsupported_current_role` means any role that treats the receiving context as current, current carrier, current source, current body, or current context. It is blocked by this boundary.

`unsupported_operator_role` means any role that treats the receiving context as operator or operation permission surface. It is blocked by this boundary.

`receiving_context_governance` means any claim that the receiving context acquired governance force, authority to decide reception, authority to validate or invalidate source, operation authority, currentness authority, publication authority, or follow-on authority. This boundary does not create receiving-context governance.

`role_inflation` means treating a bounded context role as reception, authorization, source receipt, source authority, currentness, adoption, validation, operation permission, vessel relation, derivative relation, governance, publication flow, or follow-on authority.

`role_capture` means allowing receiving-context convenience, carrier possession, latest artifact posture, registry reference, request declaration, identity preservation, or narrative framing to convert the receiving context into source, authority, current, receiver, adopter, validator, invalidator, operator, vessel, derivative, governance, permission, or publication flow.

`receiving_context_role_non_claim` means an explicit false posture preserving that role recording did not recognize reception, authorize reception, receive source, create receiving-context governance, make receiving context source/authority/current/receiver/adopter/validator/invalidator/operator/vessel/derivative, validate source, invalidate source, replace source, create adoption, authority, currentness, standing, standing propagation, vessel relation, derivative relation, operation permission, public readiness, final completion, continuation, publication flow, mutation, replay, or merge.

Receiving context remains context only.

Role is a bounded review posture, not permission.

Receiving-context role does not receive source.

Receiving-context role does not validate or invalidate source.

Receiving-context role does not authorize reception.

Carrier context review does not create carrier currentness, carrier authority, vessel relation, operation permission, or source replacement.
