## 4. Definitions

`command_output_boundary` means a boundary over recorded command output containment basis for one future command output step. It is not command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`command_output_containment_basis` means the clean command output containment result and terminal-summary basis recording one bounded command output containment event, preserved command output boundary basis, preserved recorded command execution event, audit-only execution trace, no command output, no output capture, no output/report artifact, no command result, no command success, authorization-token reuse blocked, consumed request token closed, v1 predecessor failure preserved, and returned-result containment preserved.

`bounded_command_output_containment_event` means one recorded command output containment event under the selected command output containment boundary basis. It is containment posture only and does not create command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`future_command_output_step` means a later separately bounded step that may address command output if and only if separately specified. Command output boundary may preserve basis for that future step, but it does not perform the step.

`command_output` means content emitted or captured by a separately bounded command output step. Command output boundary is not command output, and command output containment is not command output.

`output_capture` means capture of stdout, stderr, process output, command output body, or equivalent output content. This specification does not create output capture.

`command_output_report_artifact` means an artifact that reports, stores, packages, or presents command output from a live execution. This specification does not create a command output/report artifact.

`command_result` means a separately bounded result object or result posture after output has been reviewed, interpreted, shaped, or carried forward. Command output boundary is not command result.

`command_success` means a separately bounded success posture, successful execution determination, accepted exit-status posture, or equivalent success claim. Command output boundary is not command success.

`execution_trace` means audit-only evidence that a bounded execution event was recorded. Execution trace is not command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`output_as_source` means command output being treated as source standing. Output must not become source by command output boundary, command output containment, containment boundary, execution trace, capture, artifact existence, path posture, passed checks, or narration.

`result_as_authority` means command result being treated as authority. Result must not become authority by command output boundary, command output containment, artifact existence, path posture, passed checks, or narration.

`success_as_currentness` means command success being treated as currentness, public readiness, final completion, continuation, or equivalent closure. Success must not become currentness or final completion.

`consumed_request_token_closed` means the consumed request token remains closed after one clean request consumption. It must not be reopened by command output boundary, command output containment, execution trace, command output, result, success, artifact existence, path posture, passed checks, or narration.

`authorization_token_reuse_blocked` means the spent one-shot command invocation authorization token remains unavailable for second use, repeat use, standing use, durable permission, replay, re-consumption, token revival, token respawn, or reuse posture.

`output_boundary_non_claim` means an explicit false posture preserving that command output boundary did not create command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.
