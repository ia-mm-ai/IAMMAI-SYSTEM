## 7. Allowed Question Shape

The first lawful "what stands now" request shape is narrower than the generic current-state query request.

A request should be a compact object such as:

```text
WhatStandsNowRequest {
  what_stands_now_request_id: string
  query_family: "what_stands_now"
  requested_stand_now_fields: list[string]
  query_basis: string
}
```

Rules:

- `what_stands_now_request_id` must be non-empty.
- `query_family` must be exactly `what_stands_now`.
- `requested_stand_now_fields` must be non-empty.
- every requested field must be one of the bounded stand-now fields already exposed by the answered current-state result or its bounded answer/read output.
- `query_basis` must be non-empty and must identify why this bounded read is being requested.

The first lawful field set is limited to:

- `current_governing_source_run_path`
- `current_governing_ingress_run_path`
- `current_authority_artifact_path`
- `current_family_packet_path`
- `current_status_packet_path`
- `current_governing_packet_path`
- `preserved_run_count`
- `current_authority_run_count`
- `preserved_eligible_non_authority_count`
- `preserved_ineligible_count`
- `current_work_basis`
- `readout_basis`
- `handoff_basis`
- `export_basis`
- `delivery_basis`
- `application_basis`
- `answer_read_basis`
- `non_claims`

The request must not ask for:

- replay or merge permission
- continuity completion
- final identity
- final governance
- hidden provenance outside the bounded surface
- facts not already exposed by the current-state answer/read result
- ontology larger than the current executable stack carries

An implementation may map this concrete request into the generic current-state query request shape, but it must preserve the concrete `what_stands_now` family marker in the final result artifact.

## 10. Refusal / Block Conditions

Blocked "what stands now" answering must remain explicit. It is downstream concrete-question refusal/blocking, not transition refusal, re-resolution blocking, adoption blocking, effective-family consumption blocking, current-work-input blocking, current-work-operation blocking, current-state readout blocking, current-state handoff blocking, current-state export blocking, current-state delivery blocking, current-state application blocking, current-state answer/read blocking, or generic current-state query blocking.

Minimum block conditions:

- no current-state answer/read result is available
- current-state answer/read result is unreadable
- current-state answer/read result has an unrecognized, blocked, or non-answered outcome
- effective stand-now artifacts are unreadable
- canonical execution line mismatch
- effective stand-now input set is not internally coherent
- effective stand-now input set does not correspond to the current-state answer/read result
- prior family preservation is not evident where required
- replay shortcut attempted
- merge shortcut attempted
- continuity-completion shortcut attempted
- silent standing upgrade shortcut attempted
- silent fallback to stale prior-family artifacts attempted
- latest-file inference attempted without explicit current-state answer/read support
- request exceeds the bounded "what stands now" surface
- multiple current-state answer/read results conflict without an explicit bounded selection surface

Blocked "what stands now" answering should preserve enough detail to show which current-state answer/read result was considered, which stand-now request was refused, which effective references failed, and which non-claims remained required.
