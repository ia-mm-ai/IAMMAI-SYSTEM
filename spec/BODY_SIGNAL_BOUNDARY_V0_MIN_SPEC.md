# BODY SIGNAL BOUNDARY V0 MIN SPEC

## 1. Purpose

This file defines the first bounded body-signal boundary spec for the present
`IAMMAI-SYSTEM` execution line.

The current body now has post-receipt self-recognition:

- current self-orientation v3 recognizes the post-reentry body
- re-entry admissibility is recognized as downstream admission only
- re-entry receipt is recognized as downstream closure and exhaustion only
- the closed re-entry cycle is not authority
- the closed re-entry cycle is not workflow
- the closed re-entry cycle does not create follow-on permission

That makes it lawful to define what may count as body-relevant signal before
any signaling implementation is built.

A body-relevant signal is a bounded indication emitted or preserved by an
already-standing surface that may make a change, posture, refusal, openness,
receipt, exhaustion, or derivative condition visible to future lawful
surfaces.

A signal may indicate relevance. It may not create authority, permission,
currentness, workflow, roadmap, or self-generated continuation.

This file defines preconditions and refusal boundaries only. It does not
implement RADIO 22, a signal medium, a signal router, an event bus, a
nervous-system or regulation loop, workflow machinery, roadmap machinery,
next-step generation, general continuation permission, final governance,
continuity completion, final system identity, or persistence/registry law.

## 2. Status and Rank

This is an additive v0-min signal-boundary spec for the present execution line
only.

It ranks below constitutional and reference authority surfaces, including the
preserved `reference/IAMMAI/` surfaces and the current executable source,
tests, and artifacts that already stand in the repository.

This spec does not create authority. It does not define final governance. It
does not complete continuity. It does not complete final system identity. It
does not replace current executable source, tests, emitted artifacts,
self-orientation results, re-entry admissibility results, or re-entry receipt
results.

This spec defines a boundary for future body-relevant signaling. A signal that
passes this boundary would still be only an indication from a bounded source,
not a source surface, governing surface, currentness selector, permission
surface, or workflow state.

## 3. Why This Spec Is Needed Now

The body can now recognize itself after a closed re-entry cycle.

Current self-orientation v3 recognizes current/governing/current-state basis
from upstream surfaces and recognizes re-entry admissibility and re-entry
receipt only as downstream closed posture.

That creates a new pressure. Future lawful surfaces may need to know what
changed, what stands, what remains open, what blocked, what was received, what
was exhausted, and what remains non-authoritative.

Without a boundary, `signal` can drift into authority, workflow, roadmap,
recency shortcut, reusable admission, or permission. That would collapse the
distinctions preserved by current self-orientation v3 and the re-entry
admissibility/receipt cycle.

Therefore one bounded body-signal boundary spec is lawful before any signal
resolver or signaling implementation is built.

## 5. Body Signal Boundary Scope

This spec only defines what may count as body-relevant signal.

It does not:

- route signals
- rank signals
- create a signal bus
- create an event bus
- create regulation
- create a nervous system
- create workflow
- create a next-step generator
- authorize action
- create general continuation
- mutate prior artifacts
- overwrite upstream surfaces
- explain the repository for outsiders
- turn signal into source, authority, currentness, admission, receipt, or
  permission

The boundary is a precondition surface. It says what a future signal resolver
would have to preserve and refuse. It does not perform signaling.

## 6. Definition of Body-Relevant Signal

A body-relevant signal is a bounded indication from an already-standing
artifact or result that preserves a posture relevant to future lawful
recognition, refusal, or bounded relation.

A lawful signal must:

- come from an already-standing artifact or result
- preserve its source surface
- preserve its source outcome or posture
- preserve whether the posture is current, governing, derivative,
  operator-facing, open, blocked/refused, touch/admissibility, receipt,
  exhaustion, or non-claim related
- preserve source/derivative hierarchy
- preserve bounded correspondence and proportion
- avoid becoming permission or authority

A signal may indicate:

- relevance
- posture
- change
- closure
- refusal
- openness
- receipt
- exhaustion
- derivative result
- operator-facing derivative result

A signal may not:

- decide currentness
- create authority
- admit a step
- receive a step
- authorize a next step
- generate a roadmap
- become workflow state
- replace source surfaces
- convert derivative output into source
- convert re-entry admission or receipt into general permission

Already-standing surfaces may contribute body-relevant signal only if a future
resolver verifies bounded correspondence.

Candidate signal-contributing surfaces include:

- current governing/effective basis stands or changes
- current-state answer/read stands
- what-stands-now result stands
- what-remains-open result remains open
- current-state query answered or blocked
- admissibility/touch permission admitted or refused
- continuity transfer occurred
- continuity transfer receipt occurred
- received derivative participation occurred
- received derivative action permission occurred
- continuity memory seam closed
- v0 body pass confirmed
- bounded derivative vessel answered or refused
- operator-facing terminal brief rendered or blocked/refused
- re-entry admissibility admitted or blocked
- re-entry receipt received or blocked
- re-entry admission exhausted
- non-claims remain false

These candidate surfaces do not automatically emit operational signals. This
spec only says they may be signal-contributing surfaces. Any future signal
resolver must still verify source identity, outcome, hierarchy, non-claims,
and proportion.

## 8. Non-Signal and False Signal Conditions

The following must not count as body-relevant signal:

- human narration without artifact basis
- latest-file recency without explicit current/effective selector
- roadmap language
- workflow state
- ambition or intention
- vague `continue work` posture
- external-reader explanation
- derivative/API/operator output treated as source
- re-entry receipt treated as permission
- re-entry admissibility treated as reusable admission
- open surface treated as completed
- blocked/refused surface hidden
- non-claim flipped or omitted
- signal that asks to authorize action
- signal that tries to become authority
- signal that treats the closed re-entry cycle as a workflow lane
- signal that treats exhaustion as permission to continue

If a candidate indication depends on any of these conditions, it is a false
signal for this boundary and must be refused by a future implementation.

## 10. Signal Hierarchy Constraints

Signal hierarchy must remain upstream-first.

Current/governing basis signals must derive from upstream current, effective,
governing, or current-state surfaces.

Derivative/API/operator signals may only signal downstream derivative or
operator-facing posture.

Re-entry admissibility signals may only signal bounded admission or refusal
posture.

Re-entry receipt signals may only signal receipt, exhaustion, closure, or
refusal posture.

No signal from derivative, API, operator-facing, re-entry admissibility, or
re-entry receipt surfaces may determine governing or current basis.

No signal may use latest-file recency as currentness.

No signal may treat itself as authority.

No signal may grant permission.

No signal may make receipt reusable, make admission reusable, or convert the
closed re-entry cycle into a workflow lane.

## 11. Proportion / Bounded Correspondence Requirements

A signal must be proportioned to its source surface: strong enough to preserve
relevant posture, but bounded enough not to become the source, authority,
workflow, or whole-body replacement.

At minimum, a lawful signal must:

- not over-mirror by trying to carry the whole body
- not under-mirror by thinning essential posture
- preserve source id, path, family, and outcome where relevant
- preserve current/effective basis only where the source is upstream current,
  governing, effective, or current-state
- preserve open posture where the source remains open
- preserve blocked/refused posture where the source blocked or refused
- preserve receipt posture where the source is receipt
- preserve exhaustion posture where the source is re-entry receipt or closed
  re-entry cycle posture
- preserve derivative/source distinction
- preserve operator-facing derivative distinction
- preserve re-entry surfaces as downstream only
- preserve non-claims
- avoid flattening distinct surfaces into one generic state update
- avoid turning closure into permission

Signal must carry enough to audit its source relation. It must not carry so
much that it replaces the source surface.

## 12. What Signal May Carry Forward

A signal may lawfully carry:

- source surface identity
- source surface family
- source surface path
- source outcome
- selected current/effective basis if the source is upstream current,
  governing, effective, or current-state
- derivative status if the source is derivative
- operator-facing status if the source is operator-facing
- blocked/refused status
- open status
- receipt status
- exhaustion status
- non-claims
- bounded relation to current self-orientation where relevant
- bounded relation to re-entry admissibility or re-entry receipt where
  relevant

Carrying forward is not authorization.

Carrying forward is not governance.

Carrying forward is not source replacement.

Carrying forward is not currentness creation.

Carrying forward is not permission for follow-on work.

## 13. Refusal / Block Conditions for Future Signal Resolver

A future body-signal resolver would need to refuse at least these conditions:

- no artifact basis
- source surface unreadable
- source surface malformed
- source outcome missing
- signal attempts to create authority
- signal attempts to create permission
- signal attempts to authorize follow-on work
- signal treats re-entry receipt as reusable permission
- signal treats re-entry admissibility as reusable admission
- signal treats derivative/API/operator surface as source
- signal treats re-entry surface as governing/current basis
- signal infers currentness by recency
- signal hides blocked/refused posture
- signal converts open to completed
- signal omits receipt posture where receipt is the source
- signal omits exhaustion posture where re-entry receipt is the source
- signal flips or drops non-claims
- signal becomes workflow, roadmap, autonomy, or next-step language
- signal over-mirrors into whole-body replacement
- signal under-mirrors required posture
- signal widens source scope beyond selected surfaces
- signal treats the closed re-entry cycle as workflow machinery
- signal treats exhaustion as authorization to continue

Blocked signaling would not mean blocked current-state, blocked
self-orientation, blocked re-entry admissibility, or blocked re-entry receipt.
It would mean the candidate indication is refused as body-relevant signal.
