## 4. Definitions

`command_invocation_boundary` means the review membrane that may preserve a one-shot command invocation authorization token for one future invocation step. It is not command invocation, command execution, command output, command result, command success, execution permission, execution approval, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`one_shot_command_invocation_authorization_token` means the bounded token recorded by command invocation authorization that may be cited by a later separately bounded command invocation step. It remains one-shot. It is not command invocation, command execution, command output, command result, command success, execution permission, execution approval, standing invocation lane, repeat permission, currentness, final completion, continuation, reusable permission, or follow-on work.

`authorization_token_preserved` means the one-shot command invocation authorization token remains available as bounded basis for one future invocation step without being consumed, spent, discharged, reused, or promoted into invocation.

`future_command_invocation_step` means a later separately bounded step that may determine whether actual command invocation can occur. It is not created, scheduled, performed, or authorized by this specification.

`command_invocation` means causing a command module, function, script, shell, CLI, workflow, or comparable execution surface to run. Command invocation remains a separate bounded step after any boundary result.

`command_execution` means the actual live run or execution event of the command. Command invocation boundary is not command execution.

`command_output` means output emitted by separately authorized live command invocation or execution. Command invocation boundary creates no command output.

`command_result` means a result object produced by separately authorized live command execution. Command invocation boundary creates no command result.

`command_success` means successful command execution, successful return, exit status, passed execution check set, or comparable success posture from a later live run. Command invocation boundary creates no command success.

`execution_permission` means permission to execute the command. Command invocation boundary is not execution permission.

`execution_approval` means approval that command execution may be performed. Command invocation boundary is not execution approval.

`authorization_token_spent` means the one-shot command invocation authorization token has been consumed, discharged, used, or treated as spent by an actual invocation step. This boundary must keep that posture false.

`standing_invocation_lane` means any durable or reusable posture that would allow command invocation without a separately bounded step. Command invocation boundary does not create a standing invocation lane.

`repeat_invocation_permission` means any permission to reuse the consumed request, invoke more than once, reuse the authorization token, or treat one boundary result as reusable command invocation permission. Command invocation boundary does not create repeat invocation permission.

`consumed_request_token_closed` means the consumed request token remains closed after one clean consumption. It must not be reopened by authorization, boundary, invocation, execution, output, result, success, narration, path posture, artifact existence, or later carrier possession.

`invocation_boundary_non_claim` means an explicit false posture preserving that command invocation boundary is not command invocation, command execution, command output, command result, command success, execution permission, execution approval, token spend, standing invocation lane, repeat permission, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

Any actual command invocation still requires a separate bounded invocation step.
