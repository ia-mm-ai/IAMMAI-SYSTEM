## 4. Definitions

`post_invocation_command_execution` means one bounded command execution event downstream of recorded command invocation and post-invocation command execution boundary. It is not command output, command result, command success, execution permission, execution approval, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`bounded_command_execution_event` means one recorded execution event under the selected post-invocation command execution boundary basis. It is bounded to execution event posture only and does not create command output, command result, or command success.

`execution_trace` means minimal audit evidence that execution occurred, if such trace is created by a later bounded execution step. Execution trace is not command output, command result, command success, source, authority, currentness, public readiness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`command_output` means content emitted by a separately bounded output step or output-capture step. Command execution is not command output, and execution trace is not command output.

`command_result` means a separately bounded result object or result posture after output has been reviewed or shaped. Command execution is not command result, and execution trace is not command result.

`command_success` means a separately bounded success posture, successful execution determination, accepted exit-status posture, or equivalent success claim. Command execution is not command success, and execution trace is not command success.

`execution_permission` means permission to execute the command. This specification does not create execution permission, and recorded execution does not retroactively create permission.

`execution_approval` means approval that command execution may be performed. This specification does not create execution approval, and recorded execution does not retroactively create approval.

`standing_execution_lane` means any durable or reusable posture that would allow command execution without a separately bounded step. Post-invocation command execution must not create a standing execution lane.

`repeat_execution_permission` means any permission to execute more than once, replay execution, reuse execution basis as durable execution permission, or treat one execution event as a repeat lane. Post-invocation command execution must not create repeat execution permission.

`recorded_command_invocation_basis` means the clean command invocation result and terminal-summary basis recording one bounded command invocation event, one-shot authorization token spent exactly once, authorization token reuse blocked, command execution not yet performed at invocation posture, command output/result/success not created, consumed request token closed, v1 predecessor failure preserved, and returned-result containment preserved.

`post_invocation_command_execution_boundary_basis` means the clean post-invocation command execution boundary result and terminal-summary basis recording that one recorded command invocation basis is preserved for one future command execution step. It is not command execution, command output, command result, or command success.

`spent_one_shot_authorization_token` means the one-shot command invocation authorization token has already been spent exactly once by the recorded command invocation event. It must not be revived, reused, respawned, discharged again, or treated as reusable permission.

`authorization_token_reuse_blocked` means no second use, repeat use, standing use, durable lane, replay, re-consumption, token revival, token respawn, or token reuse posture may be created from the spent one-shot authorization token.

`consumed_request_token_closed` means the consumed request token remains closed after one clean request consumption. It must not be reopened by execution, execution trace, output, result, success, narration, path posture, artifact existence, later carrier possession, or spent token posture.

`execution_non_claim` means an explicit false posture preserving that command execution did not create command output, command result, command success, execution permission, execution approval, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

## 21. Closing Boundary Statement

Portable source-body verification post-invocation command execution may record one bounded command execution event downstream of recorded command invocation and post-invocation execution boundary. It preserves that command execution is not command output, command result, command success, execution permission, execution approval, standing execution lane, repeat execution permission, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.
