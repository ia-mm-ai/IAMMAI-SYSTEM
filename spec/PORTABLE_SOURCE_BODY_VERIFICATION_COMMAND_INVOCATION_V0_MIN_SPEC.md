## 4. Definitions

`command_invocation` means the bounded invocation event that may spend the one-shot command invocation authorization token exactly once. It is not command execution, command output, command result, command success, execution permission, execution approval, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`bounded_command_invocation_event` means one recorded invocation event in the portable source-body verification command invocation line. It may record token spend exactly once if all required basis is clean and bounded. It does not perform command execution.

`one_shot_command_invocation_authorization_token` means the bounded token recorded by command invocation authorization and preserved by command invocation boundary for one future command invocation step. It is one-shot and must not be treated as reusable permission.

`authorization_token_spent` means the one-shot command invocation authorization token has been used by a bounded command invocation event. Token spend is not command execution, command output, command result, command success, execution permission, or execution approval.

`authorization_token_spent_exactly_once` means the one-shot command invocation authorization token is spent once and only once by the recorded command invocation event.

`authorization_token_reuse` means any second use, repeat use, standing use, durable lane, re-consumption, replay, discharge beyond one spend, or treatment of the one-shot token as reusable permission. Authorization token reuse is prohibited.

`command_execution` means the actual live run or execution event of the command. Command invocation is not command execution.

`command_output` means output emitted by separately bounded command execution. Command invocation creates no command output.

`command_result` means a result object produced by separately bounded command execution. Command invocation creates no command result.

`command_success` means successful command execution, successful return, exit status, passed execution check set, or comparable success posture from a later live run. Command invocation creates no command success.

`execution_permission` means permission to execute the command. Command invocation is not execution permission.

`execution_approval` means approval that command execution may be performed. Command invocation is not execution approval.

`standing_invocation_lane` means any durable or reusable posture that would allow command invocation without a separately bounded step. Command invocation must not create a standing invocation lane.

`repeat_invocation_permission` means any permission to invoke more than once, reuse the consumed request, reuse the command invocation authorization token, or treat one invocation event as reusable command permission. Command invocation must not create repeat invocation permission.

`consumed_request_token_closed` means the consumed request token remains closed after one clean request consumption. It must not be reopened by invocation, execution, output, result, success, narration, path posture, artifact existence, later carrier possession, or token spend.

`invocation_non_claim` means an explicit false posture preserving that command invocation is not command execution, command output, command result, command success, execution permission, execution approval, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

Command execution, command output, command result, and command success remain separately bounded future work.
