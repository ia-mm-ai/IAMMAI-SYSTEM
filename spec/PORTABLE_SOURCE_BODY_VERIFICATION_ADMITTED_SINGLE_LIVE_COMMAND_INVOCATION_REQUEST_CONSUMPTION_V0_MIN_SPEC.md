## 4. Definitions

`admitted_request` means the already-admitted one-shot single live command invocation request. It is not request consumption until a later consumption resolver or manual review records consumption cleanly. It is not command invocation, command execution, command output, command result, command success, standing lane, repeat permission, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`request_consumption` means closing the admitted one-shot request into consumed basis only. Request consumption does not run the command. Request consumption does not create command output, command result, or command success.

`request_consumed` means the admitted one-shot request token has been consumed exactly once as closed basis. It does not mean command invocation or command execution occurred.

`consumed_request_basis` means the bounded record that a later execution review may cite as evidence that the admitted one-shot request token was consumed once. It is basis only and may be cited by a later execution review only if separately bounded.

`one_shot_consumption` means the admitted request may be consumed once only. One-shot consumption creates no standing lane and no repeat permission.

`consumption_token_closed` means the admitted request token is no longer available for another consumption. It does not create command execution permission.

`standing_invocation_lane` means any durable or reusable posture that would allow command invocation without a separately bounded review. Request consumption must not create such a lane.

`repeat_invocation_permission` means any permission to reuse the admitted request, consume it again, invoke more than once, or treat one consumption as reusable authorization. Request consumption must not create repeat permission.

`execution_permission` means permission to invoke or execute the command. Request consumption is not execution permission.

`command_invocation` means causing a command module, function, script, shell, CLI, workflow, or comparable execution surface to run. Request consumption does not create command invocation.

`command_execution` means the actual live run or execution event of the command. Request consumption does not perform command execution.

`command_output` means output emitted by a separately authorized live command invocation. Request consumption creates no command output.

`command_result` means a result object produced by separately authorized live command execution. Request consumption creates no command result.

`command_success` means successful command execution, successful return, exit status, passed execution check set, or comparable success posture from a later live run. Request consumption creates no command success.

`later_execution_review` means a future separately bounded review that may inspect consumed request basis before deciding whether command invocation or execution may proceed. This specification does not create that review.

`v2_admitted_request_basis` means selected admitted-request lineage evidence preserving outcome `SINGLE_LIVE_COMMAND_INVOCATION_REQUEST_ADMITTED`, result version `0.2.0`, failed check count zero, successor metadata, predecessor relation, returned-result containment, and no invocation/execution/output/result/success posture. It remains admission basis until consumed by a later clean consumption result.

`v1_predecessor_failure_evidence` means the visible predecessor failure line. It remains failed-lineage evidence. It is not repaired, hidden, or claimed passed by this specification.

`request_consumption_non_claim` means an explicit false claim preserved to prevent request consumption from being overread as command invocation, command execution, command output, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.
