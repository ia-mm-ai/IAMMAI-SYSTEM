# Local Relevance Medium Read-Only State Reader V0 Minimum Specification

## 1. Purpose

This file defines one local relevance medium read-only state reader for the present `IAMMAI-SYSTEM` execution line.

This is a reader-facing local state reconstruction specification after local relevance medium comparison view.

The read-only state reader is based on existing known local relevance medium artifacts through one clean comparison view.

The purpose is to read existing artifact roots, validate the known local medium chain, and emit one read-only local medium state packet showing what currently stands.

Core question:

`Given the known local relevance medium artifact roots through one clean LOCAL_RELEVANCE_MEDIUM_COMPARISON_VIEW, may one LOCAL_RELEVANCE_MEDIUM_READ_ONLY_STATE_READER be specified that reads existing artifacts, validates the standing local medium lineage, and emits one read-only local medium state packet showing what currently stands, without accepting new signals, creating new relevance objects, creating index system, registry, search, ranking, scoring, priority, validity judgment, truth judgment, authority, currentness, action, synchronization, participation authorization, participant role, runtime permission, public API, participant-facing interface, distributed network behavior, operation permission, repeated reception permission, arbitrary reception, feed, source transfer, source receipt, or follow-on work?`

This file does not create index system, registry, search surface, ranking surface, scoring, priority, validity judgment, truth judgment, authority, currentness, or runtime permission.

This file creates no repeated reception permission, arbitrary reception, or feed.

This file accepts no new signals.

## 4. Definitions

`local_relevance_medium_read_only_state_reader` means one local reader that reconstructs current local medium state from existing artifacts only.

`read_only_state_reader` means the same reader posture, with no mutation, no new signal, no new relevance object, and no new permission.

`local_relevance_medium_read_only_state_packet` means one emitted packet describing what currently stands without creating or authorizing new work.

`read_only_state_packet` means the read-only output object emitted by the reader.

`known_local_medium_artifact_roots` means the expected artifact roots from bounded relevance reception through local relevance medium comparison view.

`standing_chain` means the validated artifact lineage through comparison view.

`state_reconstruction` means reading and validating existing artifacts, not creating new objects.

`read_only` means no mutation, no new signal, no new relevance object, and no new permission.

`currently_stands` means recorded and clean artifacts through comparison view, not authority, currentness, or truth.

`selected_artifact_path` means a declared artifact path read as basis only.

`artifact_basis` means the selected artifact and preserved lineage facts used for read-only reconstruction.

`artifact_outcome` means the recorded outcome value found in a selected artifact.

`artifact_result_version` means the selected artifact result version.

`artifact_failed_check_count` means the selected artifact failed-check count.

`artifact_object_type` means the object type recorded by a selected artifact.

`chain_validation` means checking declared outcomes, versions, failed check counts, object types, preserved identifiers, artifact paths, and non-claims.

`stale_artifact` means a candidate artifact that does not match expected lineage or current selected roots.

`missing_artifact` means a required path is absent or unreadable.

`malformed_artifact` means non-JSON, non-object, missing object, or shape mismatch.

`failed_artifact` means failed_check_count is nonzero or outcome is not recorded.

`mismatched_lineage` means preserved identifiers or artifact paths do not correspond across the chain.

`overreaching_artifact` means any artifact or declared state that creates unselected behavior.
