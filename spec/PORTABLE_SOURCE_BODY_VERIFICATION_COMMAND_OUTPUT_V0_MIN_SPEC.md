## 4. Definitions

`command_output` means one bounded command-output event/posture downstream of command output boundary. It is not output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`bounded_command_output_event` means one recorded command output event/posture under the selected command output boundary basis. It records output posture only and does not capture stdout, stderr, process output, command output body, or equivalent raw output content unless a later output-capture step is separately bounded.

`command_output_boundary_basis` means the clean command output boundary result and terminal-summary basis recording one future command output step declared, command output containment basis preserved, one bounded output containment event preserved, recorded command execution event preserved, audit-only execution trace preserved, no command output, no output capture, no output/report artifact, no command result, no command success, authorization-token reuse blocked, consumed request token closed, v1 predecessor failure preserved, and returned-result containment preserved.

`future_output_capture_step` means a later separately bounded step that may capture stdout, stderr, process output, command output body, or equivalent raw output content if and only if separately specified. This command output specification does not perform that step.

`output_capture` means capture of stdout, stderr, process output, command output body, or equivalent raw output content. Command output is not output capture.

`command_output_report_artifact` means an artifact that reports, stores, packages, or presents captured command output. Command output alone does not create a command output/report artifact.

`command_result` means a separately bounded result object or result posture after output has been reviewed, interpreted, shaped, or carried forward. Command output is not command result.

`command_success` means a separately bounded success posture, successful execution determination, accepted exit-status posture, or equivalent success claim. Command output is not command success.

`execution_trace` means audit-only evidence that a bounded execution event was recorded. Execution trace is not command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`output_as_source` means command output being treated as source standing. Command output must not become source by command output recording, command output boundary, command output containment, execution trace, capture, artifact existence, path posture, passed checks, or narration.

`result_as_authority` means command result being treated as authority. Result must not become authority by command output, command output boundary, command output containment, artifact existence, path posture, passed checks, or narration.

`success_as_currentness` means command success being treated as currentness, public readiness, final completion, continuation, or equivalent closure. Success must not become currentness or final completion.

`consumed_request_token_closed` means the consumed request token remains closed after one clean request consumption. It must not be reopened by command output, command output boundary, command output containment, execution trace, capture, result, success, artifact existence, path posture, passed checks, or narration.

`authorization_token_reuse_blocked` means the spent one-shot command invocation authorization token remains unavailable for second use, repeat use, standing use, durable permission, replay, re-consumption, token revival, token respawn, or reuse posture.

`output_non_claim` means an explicit false posture preserving that command output did not create output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

It preserves that output capture is not created, command output/report artifact is not created, command result and command success do not exist, command output is not source, authority, currentness, or final completion, command output boundary remains boundary only, command output containment remains containment only, execution trace remains audit-only and is not output, result, success, source, authority, currentness, or final completion, authorization token reuse remains blocked, and the consumed request token remains closed. Output capture, command output/report artifact, command result, and command success still require separately bounded steps.
