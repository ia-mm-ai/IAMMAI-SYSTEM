## 4. Definitions

`command_boundary` means a bounded review surface that defines what a future portable source-body verification command may be allowed to check and what it must never become. It does not create that command.

`checker_only_command_posture` means a future command may only inspect declared evidence and report bounded check results if separately implemented under a future boundary. It cannot transfer, migrate, receive, authorize, deploy, host, publish, currentize, complete, continue, or create authority.

`declared_evidence_manifest_dependency` means the command boundary depends on a selected evidence-manifest result, terminal summary, or declared evidence-manifest basis. The dependency is evidence only and does not authorize command implementation or command execution.

`command_candidate` means a future command-shaped surface named for boundary review only. A command candidate is not an implemented command, executable command, command invocation, command output, or command result.

`command_implementation` means executable code, script, CLI, package entrypoint, workflow, invocation surface, or operational command behavior. Command implementation remains future work and requires a separate boundary.

`command_invocation` means an actual or instructed run of a command. This boundary does not create command invocation and does not authorize one.

`command_output` means data emitted by a command after execution. This boundary does not create command output, and future command output must not become source, authority, currentness, final completion, or follow-on authorization.

`command_success` means a future command's successful exit, passed checks, or comparable execution success. Command success must not create source, authority, currentness, operation permission, public readiness, final completion, continuation, reusable permission, or follow-on work.

`command_result` means any future bounded report produced by a separately specified command implementation. This boundary does not create a command result.

`command_authority` means treating the command, command implementation, command invocation, command output, command success, or command result as governing authority. This boundary prohibits command authority.

`command_currentness` means treating command success, command output, command result, command timestamp, local path, repository clone, artifact existence, carrier possession, latest file posture, environment state, OS, vendor, account, or narration as currentness. This boundary prohibits command currentness.

`command_output_currentness` means overreading future command output as proof that the source is current. This boundary prohibits command-output currentness.

`command_success_final_completion_overread` means treating a future successful command run as final completion, public readiness, operation permission, continuation, or follow-on authorization. This boundary prohibits command-success final-completion overread.

`path_currentness_overread` means treating a local path, path readability, path recency, or latest file posture as currentness. This boundary prohibits path currentness.

`artifact_existence_overread` means treating artifact existence or artifact readability as source standing, authority, currentness, permission, command authorization, or final completion. This boundary prohibits artifact-existence overread.

`repository_copy_overread` means treating a repository clone, repository possession, or repository copy as the body itself. This boundary prohibits repository-copy-as-body overread.

`environment_state_overread` means treating environment variables, device state, OS state, vendor state, account state, installed packages, or local runtime availability as authority, currentness, command authorization, public readiness, final completion, or deployment readiness. This boundary prohibits environment-state overread.

`checker_only_non_claim` means an explicit false posture preserving that command boundary did not implement, execute, authorize, emit, deploy, host, publish, transfer, migrate, receive, currentize, complete, continue, or create reusable permission.

`command_requires_separate_implementation_boundary` means any future command implementation must begin from a separate bounded specification and cannot be inferred from this command boundary.
