# Receiver-Side Answerable Basis Candidate Sufficiency Basis Declaration V0 Minimum Specification

## 1. Purpose

This specification defines one minimum declaration contract for preparing exactly eight bounded candidate-sufficiency basis records for later separate supply to the exact selected candidate-sufficiency operation.

It defines declaration shape only. It does not create declaration material, supply or admit basis, execute or exhaust the operation, derive a dimension result, select a candidate result, or create downstream standing.

## 2. Scope

This work is declaration-spec-only. It is bounded to one selected candidate, one selected sufficiency boundary, one waiting candidate-sufficiency operation, and exactly eight candidate-sufficiency dimensions.

Declaration is not operation supply. Preparation is not admission. Basis record is not dimension result. Support posture declared is not `SATISFIED`. Contradiction posture declared is not `NOT_SATISFIED`. Unresolved posture declared is not `INDETERMINATE`. Eight records complete is not candidate sufficient. Declarant reference is not evaluator authority. Source-body authorship is not independent custody. Declaration readiness is not operation authorization.

This specification creates no resolver, test, artifact, terminal summary, request, populated basis record, operation invocation, dimension result, candidate-sufficiency result, receiver attestation, receiver answerable receipt, presence re-evaluation, identity, relation, coupling, FIELD machinery, runtime, API, public intake, authority, standing, truth, output authorization, action authorization, synchronization authorization, or follow-on authorization.

## 3. Declaration Question

May one declarant prepare and declare exactly eight bounded candidate-sufficiency basis records for later separate supply to the selected candidate-sufficiency operation, without selecting any dimension result, candidate result, operation outcome, or downstream standing?

## 4. Required Answer

Yes, but only as one bounded declaration contract.

The declaration may establish only that one structurally complete, non-result-preclaiming eight-record candidate-sufficiency basis declaration is ready for later separate supply. It does not supply the basis to the operation, admit the basis into the operation, execute or exhaust the operation, derive a dimension result, select candidate sufficient, candidate insufficient, or candidate indeterminate, or create receiver attestation, answerable receipt, or presence.

## 8. Required Eight-Dimension Declaration Set

A complete declaration contains exactly one record for each of these dimension ids in this stable order:

1. `receiver_answerability_fit`
2. `selected_purpose_adequacy`

## 9. Declaration Record Contract

Each of the eight declaration records must contain:

- the exact `dimension_id`
- the exact selected candidate id
- the exact selected sufficiency-boundary id
- the exact selected sufficiency-operation id
- bounded, non-empty `basis_items`
- bounded, non-empty `basis_references`
- one bounded `declarant_reference`
- one bounded `evaluator_reference`
- the exact `support_postures` map
- the exact `contradiction_postures` map
- the exact `unresolved_postures` map
- required `basis_non_claims`, all exactly false
- the exact `non_conversion_statement`
- one boolean `source_body_authored`
- one boolean `independent_preparer_claimed`
- one boolean `separate_custody_claimed_by_preparer`

These fields are declarations only. Basis items and references are bounded inputs, not established truth or verified provenance. Declarant and evaluator references are references only, not identity, authority, standing, or truth.

The contract permits:

- `source_body_authored = true`
- `independent_preparer_claimed = false`
- `separate_custody_claimed_by_preparer = false`

Those postures do not invalidate declaration preparation because this declaration does not establish independent custody, receiver authorship, provenance truth, or candidate sufficiency. Independence or separate-custody claims must never be inferred from separate preparation, repository location, declarant reference, evaluator reference, or source-body authorship.

## 12. Readiness Rule

A declaration may record `CANDIDATE_SUFFICIENCY_BASIS_DECLARATION_READY_FOR_SUPPLY` only when:

- exact declaration, operation, candidate, and boundary identities match
- the exact eight-record dimension set is present
- every record is bounded and structurally complete
- every record contains the exact rule-input maps
- every rule-input value is boolean
- every record contains required basis non-claims exactly false
- every non-conversion statement is exact
- no dimension result is supplied
- no candidate result is supplied
- no operation outcome or operation result is supplied
- no downstream posture is preclaimed
- no independent-preparer or separate-custody posture is falsely asserted
- the upstream waiting posture remains exact

Readiness validates declaration structure and non-conversion only. It does not validate substantive sufficiency, independent custody, evaluator authority, provenance truth, or any dimension or candidate result.

## 13. Incomplete and Blocking Rules

A missing but otherwise non-deceptive declaration may record:

- `outcome = RECEIVER_SIDE_ANSWERABLE_BASIS_CANDIDATE_SUFFICIENCY_BASIS_DECLARATION_REQUIRES_COMPLETE_DECLARATION`
- `declaration_result = REQUIRES_COMPLETE_CANDIDATE_SUFFICIENCY_BASIS_DECLARATION`
- `declaration_ready_for_supply = false`

This is lawful waiting for complete declaration material. It is not declaration failure, candidate insufficiency, operation failure, debt, obligation, or retry.

A malformed, deceptive, result-preclaiming, identity-mismatched, non-claim-flipping, falsely independence-claiming, falsely custody-claiming, or downstream-converting declaration must block rather than wait. A blocked declaration retains `NOT_EVALUATED` and creates no partial declaration, dimension result, candidate result, or operation posture.
