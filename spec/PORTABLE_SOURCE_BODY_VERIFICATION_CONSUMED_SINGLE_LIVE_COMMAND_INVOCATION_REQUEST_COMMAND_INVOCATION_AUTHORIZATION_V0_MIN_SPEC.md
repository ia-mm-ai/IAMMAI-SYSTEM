## 4. Definitions

`command_invocation_authorization` means one bounded authorization result that may later be cited by a separately bounded command invocation step. Command invocation authorization does not itself invoke the command. Command invocation authorization does not execute the command. Command invocation authorization does not create command output, command result, or command success. Command invocation authorization is not execution permission. Command invocation authorization is not execution approval. Command invocation authorization does not create a standing lane or repeat permission.

`command_invocation_authorization_result` means the bounded record that command invocation authorization was recorded, not recorded, required additional basis, or was blocked. This specification defines the possible shape of that result. This specification does not itself record that result.

`single_command_invocation_authorization` means one command invocation authorization result for one later separately bounded command invocation step only. It is not a general authority, standing lane, repeat permission, reusable permission, or continuation.

`command_invocation_authorization_token` means the one-shot authorization token that a future recorded authorization result may create. The token is one-shot unless separately specified. It is not command invocation, command execution, command output, command result, command success, execution permission, execution approval, standing lane, repeat permission, currentness, final completion, continuation, reusable permission, or follow-on work.

`command_invocation_permission` means permission to perform the later command invocation step. A recorded command invocation authorization may be cited by that later step, but this specification does not itself perform command invocation and does not create execution permission.

`command_invocation` means causing a command module, function, script, shell, CLI, workflow, or comparable execution surface to run. Command invocation remains a separate bounded step after any authorization result.

`command_execution` means the actual live run or execution event of the command. Command invocation authorization is not command execution.

`command_output` means output emitted by a separately authorized live command invocation. Command invocation authorization creates no command output.

`command_result` means a result object produced by separately authorized live command execution. Command invocation authorization creates no command result.

`command_success` means successful command execution, successful return, exit status, passed execution check set, or comparable success posture from a later live run. Command invocation authorization creates no command success.

`execution_permission` means permission to execute the command. Command invocation authorization is not execution permission.

`execution_approval` means approval that command execution may be performed. Command invocation authorization is not execution approval.

`standing_invocation_lane` means any durable or reusable posture that would allow command invocation without a separately bounded step. Command invocation authorization does not create a standing invocation lane.

`repeat_invocation_permission` means any permission to reuse the consumed request, invoke more than once, or treat one authorization as reusable command invocation permission. Command invocation authorization does not create repeat invocation permission.

`consumed_request_token_closed` means the consumed request token remains closed after one clean consumption. It must not be reopened by authorization, invocation, execution, output, result, success, narration, path posture, artifact existence, or later carrier possession.

`authorization_non_claim` means an explicit false posture preserving that command invocation authorization is not command invocation, command execution, command output, command result, command success, execution permission, execution approval, standing invocation lane, repeat permission, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

Any actual command invocation still requires a separate bounded invocation step.
