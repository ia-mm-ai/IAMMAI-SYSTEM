## 4. Definitions

`command_output_containment_boundary` means a boundary over recorded command execution and audit-only execution trace. It may preserve one recorded command execution event and audit-only trace for one future command output containment step only. It does not create command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`recorded_command_execution_event` means the bounded post-invocation command execution event recorded downstream of recorded command invocation and post-invocation command execution boundary. It is execution-event posture only and is not command output, command result, command success, source, authority, currentness, or final completion.

`execution_trace` means audit-only evidence that a bounded execution event was recorded. Execution trace is not command output, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`future_command_output_containment_step` means a later separately bounded step that may contain command output posture if and only if separately specified. This boundary may preserve basis for that future step, but it does not perform the step.

`command_output` means content emitted or captured by a separately bounded command output step. Command output containment boundary is not command output, and execution trace is not command output.

`command_output_capture` means capture of stdout, stderr, process output, command output body, or equivalent output content. This specification does not create output capture.

`command_output_report_artifact` means an artifact that reports, stores, packages, or presents command output from a live execution. This specification does not create a command output/report artifact.

`command_result` means a separately bounded result object or result posture after output has been reviewed, interpreted, shaped, or carried forward. Command output containment boundary is not command result.

`command_success` means a separately bounded success posture, successful execution determination, accepted exit-status posture, or equivalent success claim. Command output containment boundary is not command success.

`output_as_source` means command output being treated as source standing. Output must not become source by containment boundary, capture, artifact existence, path posture, or narration.

`result_as_authority` means command result being treated as authority. Result must not become authority by containment boundary, artifact existence, path posture, or narration.

`success_as_currentness` means command success being treated as currentness, public readiness, final completion, continuation, or equivalent closure. Success must not become currentness or final completion.

`consumed_request_token_closed` means the consumed request token remains closed after one clean request consumption. It must not be reopened by command output containment boundary, execution trace, command output, result, success, artifact existence, path posture, or narration.

`authorization_token_reuse_blocked` means the spent one-shot command invocation authorization token remains unavailable for second use, repeat use, standing use, durable permission, replay, re-consumption, token revival, token respawn, or reuse posture.

`output_containment_non_claim` means an explicit false posture preserving that command output containment boundary did not create command output, output capture, command output/report artifact, command result, command success, source, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.
