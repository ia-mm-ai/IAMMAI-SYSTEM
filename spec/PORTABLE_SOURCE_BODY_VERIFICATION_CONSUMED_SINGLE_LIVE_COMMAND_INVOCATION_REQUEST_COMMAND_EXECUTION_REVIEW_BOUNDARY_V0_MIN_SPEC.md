## 4. Definitions

`consumed_request_basis` means the closed consumed-request record that the admitted one-shot request token was consumed exactly once as basis for a later review. It is not execution permission, execution approval, command invocation, command execution, command output, command result, command success, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.

`consumed_request_token_closed` means the consumed request token remains closed after one clean consumption. It must not be consumed again, reused as repeat permission, reopened, or converted into a standing invocation lane.

`command_execution_review_boundary` means this bounded specification line defining whether a later command execution review may inspect the consumed request basis. It does not itself perform the execution review.

`future_command_execution_review` means a later separately bounded review that may inspect consumed request basis and determine whether another separately bounded step is possible. This specification does not create that review result.

`execution_review_basis` means the selected reference-shaped basis used to decide whether one future command execution review may be bounded. It is basis only and is not execution permission or execution approval.

`execution_review_admission` means admitting consumed request basis into a later command execution review boundary as inspectable basis only. It does not authorize invocation or execution.

`execution_permission` means permission to invoke or execute the command. This boundary creates no execution permission.

`execution_approval` means approval that a command may be invoked or executed. This boundary creates no execution approval.

`command_invocation` means causing a command module, function, script, shell, CLI, workflow, or comparable execution surface to run. This boundary does not create command invocation.

`command_execution` means the actual live run or execution event of the command. This boundary does not perform command execution.

`command_output` means output emitted by a separately authorized live command invocation. This boundary creates no command output.

`command_result` means a result object produced by separately authorized live command execution. This boundary creates no command result.

`command_success` means successful command execution, successful return, exit status, passed execution check set, or comparable success posture from a later live run. This boundary creates no command success.

`standing_invocation_lane` means any durable or reusable posture that would allow command invocation without a separately bounded review. This boundary creates no standing invocation lane.

`repeat_invocation_permission` means any permission to reuse the consumed request, invoke more than once, or treat one consumed request as reusable authorization. This boundary creates no repeat invocation permission.

`consumed_request_reopen` means treating the closed consumed request token as open, reusable, unconsumed, again consumable, or available for another request-consumption path. This boundary must not reopen the consumed request token.

`request_consumption_non_claim` means an explicit false posture preserved to prevent request consumption from being overread as command invocation, command execution, command output, command result, command success, execution permission, authority, currentness, final completion, continuation, reusable permission, derivative reception, vessel relation, another reception request, or follow-on work.
