# IAMMAI First-Pass Currentness Record

## 1. Purpose

This file defines the first-pass currentness record object as the next practical continuity-housing move after the first-pass lineage record.

Its job is to make one bounded continuity object explicit enough that operative currentness stops living only in bridge memory, file naming, reader synthesis, and skilled reconstruction, and starts becoming a housed object in its own right.

It does not:

- define a constitutional rewrite
- define a continuity-family master map
- define a current-state dashboard
- define a storage architecture
- define a graph or database design
- define a distributed systems plan
- define a schema
- replace continuity, admissibility, accession, standing, vessel, bridge, review, or current-state surfaces already standing in the body

This file is additive only. It does not replace the continuity surfaces, the admissibility surfaces, the accession family, the standing bridges, the vessel posture surfaces, the review surfaces, or the current-state entry surfaces already standing in the repository.

## 2. Why This Note Is Needed Now

Operative currentness is still one of the most dangerous truths to leave in reader memory.

A skilled reader can often reconstruct what governs now for a bounded matter. That reconstruction may be lawful and even careful. It still leaves too much of present operation dependent on remembering which bridge carried what, which later surface narrowed what, which review remained current, and which nearby readable surfaces remain visible but are no longer operative for the bounded scope at hand.

The body therefore needs one first practical move toward currentness objecthood. It does not need a whole current-state engine. It needs one small object that can house, for one bounded scope, what governs now here, in what posture, and on what basis.

This note exists to define that move without overbuilding it.

## 3. What The First-Pass Currentness Record Answers

The first-pass currentness record answers the bounded question:

**What is the smallest explicit object that can house present governing surface for one bounded scope without falsifying continuity?**

This is not yet a full current-state engine question.

It is also not yet a storage architecture question.

It is a narrower object question. The aim is to house one bounded currentness claim in a way that keeps present governing relation explicit without flattening nearby history, nearby bridges, or nearby visible but non-operative surfaces.

## 4. The First-Pass Currentness Record Object

The first-pass currentness record object is a small continuity object for one currentness claim only.

It houses:

- what bounded scope is being spoken of
- what surface presently governs that scope
- in what posture that surface presently governs
- what basis supports that currentness claim
- what nearby visible surfaces remain non-current for that same scope

In first-pass form, the object may be read as:

```json
{
  "currentness_record_id": "...",
  "recorded_at": "...",
  "scope_ref": "...",
  "current_ref": "...",
  "current_posture": "...",
  "basis_refs": ["..."],
  "non_current_refs": ["..."]
}
```

This object is anti-drift and anti-mush.

It houses one currentness claim for one bounded scope only. It records currentness rather than computing it. It does not attempt to act as a whole-body dashboard, a current-state engine, or a hidden authority allocator.

## 5. Minimum Fields

### `currentness_record_id`

What it means:
A bounded identifier for this one currentness record.

Why it is needed:
The currentness claim itself must be referable as an object rather than only as a reader conclusion.

What it must not collapse into:
It must not collapse into a claim that the record itself has become sovereign current-state truth or final current-state machinery.

### `recorded_at`

What it means:
The time at which this currentness claim was recorded as an explicit object.

Why it is needed:
Currentness needs explicit recording posture rather than only later reconstruction.

What it must not collapse into:
It must not collapse into the claim that recency alone makes something current. Recorded time is not the whole meaning of currentness.

### `scope_ref`

What it means:
The bounded reference for the scope whose currentness is being claimed.

Why it is needed:
Currentness must stay bounded. Without explicit scope, currentness drifts from one matter into a larger body than was actually reviewed.

What it must not collapse into:
It must not collapse into a whole-body totality claim. One currentness record is not the currentness of the whole repository.

### `current_ref`

What it means:
The bounded surface that presently governs for the named scope.

Why it is needed:
The object must say what currently governs here rather than forcing a reader to infer it from scattered bridges, reviews, and later posture files.

What it must not collapse into:
It must not collapse into a claim that `current_ref` replaces all nearby visible surfaces, or that the record itself grants authority to that surface.

### `current_posture`

What it means:
The posture in which `current_ref` presently stands for the named scope.

Why it is needed:
Currentness is not only which surface is current. It is also how that surface currently stands, for example as operative, narrowed, deferred, bridge-carrying, or review-bearing.

What it must not collapse into:
It must not collapse into a final global posture vocabulary for the whole body. First-pass posture typing should stay small and revisable.

### `basis_refs`

What it means:
The bounded references that justify why `current_ref` is being recorded as current for this scope.

Why it is needed:
Currentness should not live by atmosphere. The object must say what present basis supports the currentness claim.

What it must not collapse into:
It must not collapse into an exhaustive provenance graph, a whole dossier dump, or a claim that basis surfaces become non-current merely because they are basis.

### `non_current_refs`

What it means:
The bounded nearby references that remain visible for the same scope but should not be mistaken as presently governing there.

Why it is needed:
Currentness is partly an anti-confusion problem. The body often keeps earlier bridges, earlier reviews, earlier posture notes, and readability surfaces visible. Without explicitly naming non-current neighbors, a reader can mistake visibility for operativeness.

What it must not collapse into:
It must not collapse into condemnation, erasure, or a statement that the non-current surfaces have lost lineage value.

## 6. Why `current_posture`, `basis_refs`, and `non_current_refs` Matter

Currentness is not only “what is current.”

Currentness also requires:

- how the current surface presently stands
- why that currentness claim is justified
- what nearby visible surfaces remain non-operative for the same scope

Without `current_posture`, the object becomes a weak pointer that cannot say whether the current surface is presently operative, narrowed, deferred, or current only as review pressure.

Without `basis_refs`, the object collapses toward unsupported status speech. A reader is told what is current but not why that claim is lawful.

Without `non_current_refs`, the object collapses toward generic readability aid. It may point at one current surface, but it does not protect the reader from mistaking nearby visible history, readability surfaces, or earlier bridges as though they still governed the same scope.

Together, these fields make the object currentness-bearing rather than merely helpful. They force the record to state not only what is current, but how, why, and against which visible non-current neighbors.

## 7. Currentness Is Not Authority

The first-pass currentness record locates present governing surface.

It does not become that governing surface.

If a currentness record says that one bridge, one posture decision, or one review presently governs for a bounded scope, the authority remains in that underlying surface and in the ranked body that lawfully supports it. The currentness record only houses that relation explicitly.

This object is therefore authority-locating rather than authority-generating.

If that distinction is lost, the body gains a counterfeit dashboard layer that begins to pretend it creates truth merely by listing what seems current.

## 8. Recorded Before Computed

First-pass currentness should be recorded explicitly before any future attempt to compute it.

The reason is simple. Currentness in this body is rank-sensitive, bridge-sensitive, matter-sensitive, and anti-collapse by design. A premature computed currentness layer would be tempted to treat recency, adjacency, filename signals, or graph reachability as though they were already lawful truth.

That would risk building an inference system pretending to be currentness.

Recorded-first posture is smaller and safer. A recorded object can say, for one bounded scope, what presently governs, on what basis, and against what visible non-current neighbors. Only later, if still lawful and still wanted, may the body ask whether some part of that relation should become partially computed.

## 9. What This Object Is Not

This object is not:

- the final current-state model
- the final storage architecture
- a dashboard
- a graph or database solution
- a computed currentness engine
- a canonical replacement for law, proof, decision, bridge, or review surfaces themselves

It is also not a claim that one currentness record can summarize the whole body. It is the next practical continuity-housing move after lineage only.

The reduced shape is preferred at this stage because the body needs housed operative currentness more urgently than it needs a large current-state ontology. A smaller object can stop present governing truth from living only in skilled remembering without pretending the whole current-state problem is solved.
