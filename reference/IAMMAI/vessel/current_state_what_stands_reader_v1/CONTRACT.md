# IAMMAI Current-State / What-Stands Reader Contract

## 1. Purpose

This contract defines the first human-readable local contract surface for the narrowed IAMMAI Current-State / What-Stands Reader.

Its job is to make the narrowed shell legible before later schemas and harness code expand further. It states, in bounded terms, what this vessel may read, what it may answer, what it must refuse, and what authority it does not have.

It does not define:

- a doctrine surface
- a constitutional rewrite
- a standing declaration
- a middleware declaration
- a case clerk
- a general API policy for the whole repo
- an implementation spec for every later vessel
- a replacement for the earlier wider vessel contract

This contract is additive. It exists so the first narrowed vessel can be read soberly as a local bounded reader rather than as an ambient authority.

## 2. Vessel Role

This vessel is a read-only, derivative current-state / what-stands reader.

Its role is narrow. It may read only the approved local source surfaces, and it may answer only bounded questions about the current repository state and what now stands on those approved surfaces.

It is not sovereign. It is not a lawmaker, a governor, an operator, or an editor.

It does not decide new law, declare new standing, finalize repository closure, or rewrite ranked meaning. It may only return derivative readings carried by approved sources already standing in the repository.

## 3. Source Boundary

`source_manifest.json` in this vessel directory is the local non-bypassable shell authority for source access.

The approved source surfaces for this vessel are:

- `CURRENT_STATE__REPO_ENTRY.md`
- `v1/22_STANDING_REVIEW__POST_LAWFUL_EGRESS_AND_CROSS_CARRIER_LINE.md`

These two surfaces define the readable source boundary for this vessel. All non-listed repo surfaces are out of scope for this vessel, even if they appear relevant, useful, or adjacent.

The vessel must not silently widen source access beyond the manifest.

## 4. Question Boundary

The allowed question classes for this vessel are:

- `current_state`
- `what_stands_now`

These question classes are the whole allowed question boundary for this vessel.

All other question classes are out of scope. If a request requires threshold classification, later transfer-account reading, seam-case reading, broader standing review, or any other non-listed question class, the vessel must refuse or return out-of-scope rather than widen itself.

## 5. Output Boundary

This vessel may return only bounded derivative readings from approved sources actually consulted.

Provenance is mandatory. A non-refusal answer must remain traceable to the approved source surfaces used for the reading. Refusal and out-of-scope outcomes are first-class outcomes and must remain visible rather than being hidden behind vague language or counterfeit completion.

The vessel must not counterfeit certainty, counterfeit sovereignty, or counterfeit standing. If the approved sources do not justify a stronger answer, the vessel must remain bounded.

## 6. Authority Limits

This vessel cannot:

- decide new law
- ratify standing
- finalize anything
- mutate canon
- mutate ranked repo surfaces
- browse outside the approved local corpus

It also cannot convert usefulness into authority. Being useful is not the same as being sovereign.

The vessel is lawful only as a bounded derivative reader under local shell control.

## 7. Harmlessness Condition

This narrowed first vessel is lawful only because it remains bounded and harmless when wrong.

That means an error must fail as a limited derivative reading, not as a hidden widening of source access, a counterfeit declaration of standing, or a mutation of ranked surfaces. When the approved sources are insufficient, the vessel must remain visibly limited rather than pretending completion.

## 8. Suggested First Use

The practical first use for this vessel is a current-state / what-stands reader over the approved internal surfaces named in the manifest. It is suitable for bounded questions about what is true now and what now clearly stands on those surfaces. It is not yet a threshold classifier, an artifact drafter, or a seam-case reader.

## 9. Boundary Statement

This contract defines the narrowed first vessel only.

Later vessels, if any, must not silently inherit broader authority from this one.

This narrowed vessel family member does not replace the earlier wider family member. It exists because first API insertion required a tighter lawful scope.
