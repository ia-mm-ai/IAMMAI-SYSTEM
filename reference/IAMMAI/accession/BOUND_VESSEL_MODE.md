# IAMMAI Bound Vessel Mode

## 1. Purpose

This file defines Bound Vessel Mode as the accession sublayer where one admitted external slice may operate in an explicitly bounded vessel relation under body law.

Its job is to make explicit what one admitted slice may and may not do once Bound Vessel Mode is separately granted, without collapsing that mode into whole-system conversion, standing, canon, closure, or native constitutional source.

It does not define:

- a constitutional rewrite
- a sovereign authority layer
- a Contact Law file
- an eligibility file
- a shadow-mode file
- an accession proof file
- an admission decision
- a migration strategy memo
- a product integration handbook
- a roadmap
- a project-management surface

This file is additive only. It does not replace the constitutional core, the admissibility surfaces, the continuity surfaces, the standing-facing review surfaces, the vessel-family surfaces, [`accession/CONTACT_LAW.md`](./CONTACT_LAW.md), [`accession/ACCESSION_ELIGIBILITY.md`](./ACCESSION_ELIGIBILITY.md), [`accession/SHADOW_SLICE_MODE.md`](./SHADOW_SLICE_MODE.md), [`accession/ACCESSION_PROOF_SLICE.md`](./ACCESSION_PROOF_SLICE.md), [`accession/ADMISSION_DECISION.md`](./ADMISSION_DECISION.md), or the master map in [`accession/ACCESSION_LAYER.md`](./ACCESSION_LAYER.md).

## 2. Why This File Is Needed Now

After admission, the body still needs a separate bounded operational posture before anything external can function as a vessel.

Without Bound Vessel Mode, admission either stays inert or gets promoted informally into broad operational privilege. That would let admitted relation drift into hidden authorship, hidden expansion, or hidden inheritance without a lawful operational membrane.

Bound Vessel Mode is therefore needed so one admitted slice can operate under explicit law without merger, prestige laundering, or silent authority carryover.

This file exists to make that posture legible without overbuilding it.

## 3. Existing Position in the Body

Bound Vessel Mode is the next sublayer already mapped in [`accession/ACCESSION_LAYER.md`](./ACCESSION_LAYER.md).

It follows Contact Law, Accession Eligibility, Shadow Slice Mode, Accession Proof Slice, and Admission Decision. It precedes revocation.

This file therefore binds a mapped sublayer rather than inventing a new family. It stands at the point where one admitted slice may or may not function in bounded vessel relation.

## 4. What Bound Vessel Mode Answers

Bound Vessel Mode answers the bounded question:

**Under what lawful conditions may one admitted external slice operate in bounded vessel relation without being generalized beyond itself?**

This is a post-admission, pre-revocation operational question only.

It asks whether one admitted slice may perform bounded derivative function under body law within explicit scope. It does not yet ask whether any standing consequence follows, whether any canon consequence follows, or whether anything has reached closure.

## 5. Vessel Mode Is Not Native Source

The following distinctions must remain explicit.

- Admission is not Bound Vessel Mode.
- Bound Vessel Mode is not standing.
- Bound Vessel Mode is not canon.
- Bound Vessel Mode is not nativeness.
- Bound Vessel Mode is not native constitutional source.

Bound Vessel Mode means only that one admitted slice has been separately granted a bounded vessel relation for derivative, source-limited operation.

It does not create:

- native constitutional authorship
- standing-facing consequence by itself
- canon-facing consequence by itself
- whole-system belonging
- silent authority inheritance

Bound Vessel Mode is therefore explicit bounded operation, not native source promotion.

## 6. What Bound Vessel Mode Grants

Bound Vessel Mode legitimately grants only the following in bounded form.

### One Explicit Admitted Slice Only

Bound Vessel Mode applies to one admitted slice only. It does not spread by adjacency, usefulness, ownership, familiarity, or atmosphere.

### Bounded Operational Relation

Bound Vessel Mode creates a bounded operational relation under explicit law. The relation must remain typed, limited, and non-generalizing.

### Derivative, Source-Limited Function

Bound Vessel Mode permits derivative function only. The slice remains source-limited and may not improvise authority beyond the sources, contract, and bounded operational scope lawfully attached to it.

### Preserved Source Legibility

Bound Vessel Mode does not erase source. The slice remains provenance-legible and source-legible while operating.

### Preserved Jurisdiction Distinction

Bound Vessel Mode does not collapse jurisdictions. The slice may function under body law without being rewritten as though it were native constitutional matter.

### No Silent Authority Carryover

Bound Vessel Mode permits no hidden authority transfer from founder relation, external prestige, usefulness, proximity, or prior system position.

### Explicit Scope-Bounded Outputs Or Functions

Bound Vessel Mode may permit bounded outputs or bounded functions only inside the explicit operational scope separately attached to the slice.

Outside that scope, the slice has no vessel privilege.

## 7. What Bound Vessel Mode Does Not Grant

Bound Vessel Mode does not lawfully do the following.

- It does not create whole-system inheritance.
- It does not create native constitutional source status.
- It does not create standing by vessel mode alone.
- It does not create canon.
- It does not create closure.
- It does not create adjacent expansion.
- It does not create prestige promotion.

Bound Vessel Mode must also not be granted by founder ownership, usefulness, familiarity, urgency, or proximity. Those do not create hidden vessel privilege.

Bound Vessel Mode is therefore bounded and non-generalizing. It is a typed operational permission, not a broad upgrade.

## 8. Bound Vessel Mode and Preserved Origin

A bound vessel slice remains source-legible and jurisdiction-distinct.

That means provenance remains visible, origin remains visible, and the conditions under which the slice entered vessel mode remain visible. Bound operation does not rewrite the slice into native constitutional authorship and does not clean away the path by which the slice arrived.

Carried relation does not become native constitutional source. Bound Vessel Mode cannot erase source relation, admission history, proof history, or conditions of entry.

If vessel operation requires erasing provenance, suppressing jurisdiction distinction, or pretending that the slice always already belonged as native constitutional source, then the vessel operation is counterfeit.

## 9. Operational Outcomes and Narrowing

Bound Vessel Mode lawfully permits bounded operational outcomes only.

### Continue In Bounded Vessel Mode

The slice may continue in bounded vessel mode where it remains inside explicit scope and continues to preserve derivative, source-limited, non-sovereign posture.

### Narrow Scope

The slice may be narrowed where its operative scope should become smaller, sharper, or more conditional under body law.

### Pause

The slice may be paused where continued operation is not presently lawful, not presently needed, or not presently clear enough to continue.

### Revoke Later Under Separate Revocation Law

The slice may later be revoked under separate revocation law.

Bound Vessel Mode is therefore not irreversible and does not create permanent privilege by default. Narrowing, pausing, or later revocation do not erase lineage.

## 10. What Bound Vessel Mode Does Not Grant

Bound Vessel Mode does not itself create:

- standing
- authority beyond scope
- canon
- closure
- whole-system belonging

It also does not grant:

- founder privilege
- usefulness privilege
- urgency privilege
- familiarity privilege
- proximity privilege

Even when operative, Bound Vessel Mode remains a bounded admitted-slice posture only.
