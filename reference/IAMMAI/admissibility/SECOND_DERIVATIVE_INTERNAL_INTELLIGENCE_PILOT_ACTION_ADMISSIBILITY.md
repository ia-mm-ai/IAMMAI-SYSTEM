# IAMMAI Second Derivative Internal Intelligence Pilot Action Admissibility

## 1. Purpose

This file defines second-pilot admissibility only for derivative internal intelligence participation.

Its job is to answer, in one bounded admissibility note:

- whether one further pilot action is admissible after the first executed pilot case
- what new bounded evidence a second pilot would need to produce that the first did not
- whether same-branch repetition would be lawful or merely momentum
- whether a second pilot, if any, should move to another already-mature branch
- what supervision, refusal, trace, and review conditions would be mandatory
- what even a lawful second pilot would still not open

It does not define:

- a constitutional rewrite
- an implementation plan
- a runtime contract
- a vessel rollout
- an agent framework
- a reusable lane design
- a second-pilot execution note
- a work queue
- a roadmap
- a README
- a project-management note
- a manifesto

This file is additive only. It does not replace repo-scale current-state, readability, rank, or lineage surfaces. It also does not replace existing admissibility, implementation, continuity, runtime, or vessel posture surfaces already standing in the body.

## 2. Why This Note Is Needed Now

The first executed pilot creates a new admissibility question.

The question is no longer whether one pilot action can exist in principle. That question was already narrowed by the first pilot boundary and then partially answered by the first execution case.

The new question is whether one further pilot could ever be lawful without laundering the first case into a standing lane.

This question arises from real execution, not from enthusiasm. The main risk now is normalization by success: treating “it worked once” as though it had already become reusable permission. This note exists to stop that over-reading before it begins.

## 3. What Already Stands Around This Question

The second-pilot question stands only because the following already stand.

- `admissibility/DERIVATIVE_INTERNAL_INTELLIGENCE_PARTICIPATION_BOUNDARY.md` already defines the gate in principle and keeps any future participant derivative, supervised, non-sovereign, and source-limited.
- `admissibility/FIRST_DERIVATIVE_INTERNAL_INTELLIGENCE_PILOT_ACTION_BOUNDARY.md` already narrowed the first lawful pilot action to one singular low-sovereignty candidate.
- `admissibility/FIRST_DERIVATIVE_INTERNAL_INTELLIGENCE_PILOT_ACTION_EXECUTION_CASE.md` already records that one first pilot was actually executed in bounded form and explicitly states that this did not create second-action permission.
- `implementation/CURRENT_IMPLEMENTATION_SURFACES__POST_BRANCH_CONFORMANCE.md` already shows that implementation now contains more than one completed first-pass mature branch line.
- `implementation/CURRENT_CONTRIBUTION_ROLE_SURFACES.md` already shows that the contribution branch is one such mature branch.
- `implementation/CURRENT_DECISION_RECORD_SURFACES__POST_CONFORMANCE.md` already shows that the decision branch is another such mature branch, with schema presence, invalid fixtures, checker support, and explicit current branch state.

Second-pilot admissibility therefore comes after gate definition, first-pilot narrowing, first execution case law, and visible mature-branch evidence. It does not come before them.

## 4. What A Lawful Second Pilot Would Need To Justify

A lawful second pilot would need to produce new bounded evidence that the first pilot did not already produce.

The first pilot already proved one thing in practice:

- one low-sovereignty invalid-fixture action can be executed under supervision in one already-mature branch

A second pilot is therefore lawful only if it answers a different bounded question.

The strongest bounded candidate question is:

- whether the same narrow action remains lawful in a different already-mature branch under the same supervision discipline

That is new evidence. It tests whether the first case was only branch-local accident or whether the same tightly bounded action can remain lawful across more than one already-mature implementation branch without widening into a lane.

Anything weaker than that risks being only momentum.

## 5. Current Best Read Of Whether A Second Pilot Is Admissible

The current best bounded read is: **yes, one second pilot is admissible in principle, but only as a singular cross-branch evidence-seeking case.**

The strongest bounded candidate is:

**drafting one additional invalid fixture for the already-standing decision-record schema inside the already-mature decision branch.**

This is the strongest current candidate because:

- it keeps the action type identical to the first pilot at the lowest-sovereignty end of the allowed derivative task set
- it produces new evidence the first case did not produce
- it uses a branch that is already mature in the same relevant way: objecthood, schema presence, invalid fixtures, checker, and explicit current branch state
- it avoids turning second-pilot admissibility into a broader permission question

This should still be read as:

- singular
- evidence-seeking
- non-generalizing
- not yet executed
- not yet a standing lane

## 6. Same-Branch Repetition vs New-Branch Evidence

Repeating the same action in the same branch is too weak as evidence.

On current visible body law, same-branch repetition would read primarily as momentum by familiarity rather than as new admissibility evidence. It would test less than the first case already made visible and would increase the risk of normalization through comfort with one branch’s supervision pattern.

If a second pilot is admissible at all, another already-mature branch is the cleaner evidence source.

The present decision branch is the clearest candidate for that narrower role because it already stands with:

- explicit objecthood
- explicit schema admission and geometry clarification
- first-pass schema presence
- invalid fixtures
- bounded checker support
- explicit current branch state

That makes cross-branch comparison possible without widening into general branch access.

## 7. Mandatory Supervision, Refusal, Trace, And Review Boundaries

Even for a second pilot, all of the following would still need to hold.

- explicit human selection of the task
- explicit human selection of the host branch
- explicit supervision surface rather than ambient oversight
- refusal if the work drifts beyond one bounded invalid-fixture action
- refusal if the work begins to imply broader permission, normalization, or branch-family carry
- traceability as a separate second case rather than as continuation of the first one
- explicit human review before any repo admission
- no self-chaining
- no self-expansion

If later execution were ever chosen, the same review-before-admission and checker-visible discipline used in the first case would still need to remain intact. This note does not execute that second case. It only states the admissibility boundary under which it could later be considered.

## 8. What This Note Still Does Not Open

Even a lawful second pilot would still not open:

- a standing lane
- broad branch access
- runtime, registry, API, or vessel implementation in general
- autonomous developmental participation
- third-action permission by default
- generalized repeatability

It would also not allow the participant to determine currentness, witness truth, governance force, canon, or source.

Two bounded cases would still be two bounded cases, not a lane.

## 10. What Remains Open

The following remain open after this note.

- whether the second pilot is actually activated now
- what exact supervision surface would govern execution
- what exact trace or log surface would house repeated pilot cases
- whether any third pilot is ever lawful
- whether any lane is ever lawful after more evidence

These remain open on purpose. A second pilot should not inherit activation merely because it is admissible in principle.
