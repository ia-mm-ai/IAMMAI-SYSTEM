# IAMMAI Source Admissibility

## 1. Purpose

This file defines source admissibility as a bounded admissibility subdomain inside the current IAMMAI body.

Its job is to clarify when a preserved surface may or may not be used as a lawful source for the relation now being claimed, while keeping that question distinct from source existence, source authority, standing, canon admission, and governance force.

It does not:

- rewrite the constitutional protocol
- rewrite `runtime/VALIDATOR_CONTRACT.md`
- rewrite `v1/05_STANDING_CRITERIA.md`
- rewrite `v1/runtime/SOURCE_SELECTION_AND_ADMISSIBILITY_POSTURE.md`
- define a canon admission procedure
- define a retrieval strategy or filesystem policy
- patch a runner or runtime flow
- act as a README or project-management note

This file is additive. It does not replace the existing v1 source-selection posture or other ranked surfaces. It binds one admissibility domain more explicitly inside the body already standing.

## 2. Why This File Is Needed Now

The current body already has source admissibility posture.

That posture is already stated most directly in `v1/runtime/SOURCE_SELECTION_AND_ADMISSIBILITY_POSTURE.md`, and it already rejects directory presence, recency, retrieval ease, and filesystem convenience as hidden substitutes for lawful source use.

The body now benefits from a clearer bounded file for this subdomain because the repository has become denser:

- more preserved runs exist beside one another
- lineage visibility is stronger
- derivative readability surfaces are more available
- proof-bearing outputs are more visible across the v1 line

That density improves legibility, but it also increases the risk that preserved existence, readability, proof-bearing status, or local convenience may start to impersonate lawful source legitimacy if source admissibility remains under-specified outside its current runtime-law root.

This file exists to reduce that risk by bounded clarification, not by replacing the earlier root posture.

## 4. What Source Admissibility Answers

Source admissibility answers the bounded question:

**May this preserved surface be used as a lawful source for the relation now being claimed?**

That question is not answered in the abstract.

It is relation-bound, matter-bound, and posture-bound.

This means the same preserved surface may be:

- admissible for one relation
- inadmissible for another relation
- readable and useful as evidence without being admissible as the lawful source for the current claim

Preserved existence alone does not answer the question. A file, run, artifact body, report, summary, or directory may be real, preserved, and retrievable while still failing to qualify as the lawful source for this matter, this relation, or this bounded review posture.

## 5. Source Existence, Source Admissibility, and Source Authority

These three must remain distinct.

### 5.1 Source existence

Source existence means that a surface or artifact is really present in the preserved body and can be encountered, retrieved, or reconstructed.

Existence alone does not make it a lawful source.

### 5.2 Source admissibility

Source admissibility means that a preserved surface may lawfully be used as source for the specific relation and matter now being claimed.

This is a bounded use question, not a blanket status conferred on a file forever.

### 5.3 Source authority

Source authority is a further rank question about whether a source has authoritative force for the claim being made.

Admissible source status does not automatically create authoritative source status. Convenience, readability, proof-bearing status, or local retrieval habit do not grant authority.

## 6. Source Classes and Relation Classes

The visible body already supports the need to preserve source class and relation class.

At minimum, the current repo body explicitly distinguishes:

- ordinary anchor source
- continuity predecessor source

It also already supports more than one relation class in practice, including:

- canonical artifact anchoring
- predecessor succession
- continuity relation
- seam or transfer relation
- bounded review relation

Source admissibility must therefore be read through fit between source class and relation class, not through the generic statement that something is “a source.”

The question is not whether a preserved surface is source-like in atmosphere. The question is whether it is admissible as this class of source for this class of relation.

## 7. Anchor and Predecessor Source Reading

Anchor-source admissibility and predecessor-source admissibility must remain distinct.

An anchor source is used to preserve canonical artifact anchoring. In the current body, the ordinary anchor source keeps later continuity work subordinate to preserved canonical ordinary reality rather than to sequence alone.

A predecessor source is used to preserve lawful predecessor succession. In the current body, the continuity predecessor source keeps append-oriented continuity legible across later turns where predecessor succession matters.

These relations must not be flattened.

Predecessor succession may matter without replacing anchor discipline. A predecessor source cannot lawfully replace canonical anchor relation merely because it is later in sequence, more convenient to retrieve, or more visibly continuity-shaped.

Append-oriented or continuity-oriented succession must therefore remain subordinate to anchor relation where the governing posture requires that subordination.

## 8. Matter Coherence and Relation Coherence

Source admissibility depends on fit to the matter and relation being claimed.

A preserved artifact may be real, readable, proof-bearing, and even locally useful while still being inadmissible as source for the present matter.

Matter coherence requires that the source remain lawfully tied to the matter under review rather than merely resembling it, sitting near it, or being available in the same preserved body.

Relation coherence requires that the claimed use remain lawful for the relation being preserved. A continuity predecessor source must remain coherent with the anchor relation it depends on. A seam or transfer relation must preserve origin legibility rather than laundering arrival into native source. A bounded review posture must not treat visible proof or readable summary as though it automatically settles the governing source relation.

Co-location, naming resemblance, family similarity, recency, and rhetorical force are not enough.

## 9. Source Selection Posture

The current body already points toward an explicit source-selection posture and explicit recorded source choice.

Source selection must remain visible enough that later readers can recover:

- what source was selected
- what class of source it was
- what relation was being preserved
- what matter coherence made that selection lawful

Where bounded local defaults are used, they may operate only among already admissible candidates. They must not create admissibility, and they must not be mistaken for protocol law.

This means:

- directory presence is not lawful selection
- recency is not lawful selection
- retrieval ease is not lawful selection
- readability alone is not lawful selection
- convenience is not lawful selection

Recorded selection is part of lawful source use, not an optional note after the fact.

## 10. What Source Admissibility Does Not Grant

Source admissibility does not itself create:

- truth
- standing
- canon
- governance authorization
- blanket authoritativeness

It may support lawful handling, lawful review, lawful checking, or lawful continuity work. It does not thereby become standing state, canon admission, governance force, or universal source authority.

A source may be admissible for a bounded use without becoming the authoritative source of the whole matter.

## 12. Anti-Collapse Rules

A conforming source-admissibility posture must not allow:

- preserved is not source
- source is not admissible source by default
- admissible source is not authoritative source
- readability is not source authority
- recency is not legitimacy
- directory presence is not lawful selection
- retrieval convenience is not lawful source legitimacy
- predecessor succession does not replace anchor relation
- proof-bearing does not automatically become source authority
- derivative readability does not automatically become lawful source use
- recorded availability does not automatically become matter coherence

## 13. Closing Boundary Statement

This file defines source admissibility only.

Later files may elaborate other admissibility domains. This file does not attempt to solve canon admission, standing review, source authority, or future source cases in one step.

It exists so lawful source use can be read more explicitly inside the current IAMMAI body without rewriting prior lineage and without laundering convenience into authority.
