# IAMMAI v1 Registry / Preservation Posture

## 1. Purpose

This file defines the bounded v1 registry and preservation posture for the first controlled proof slice.

Its job is to state how v1 preservation is to be understood for the first proof slice after body formation, conformance, and optional envelope-bearing emission, and before concrete emitter re-derivation hardens placement choices by convenience.

It does not define:

- a constitutional rewrite
- a seam declaration
- an authority or inheritance map
- an artifact-boundary decision
- a schema file
- an emitter implementation patch
- a storage-engine design
- a continuity redesign
- a project-management roadmap
- a generic README for the whole repo

It is a bounded registry and preservation posture note.

## 2. Why This File Is Needed Now

V1 now has body schemas, conformance posture, runtime flow, emission plan, and operator runbook.

Preservation posture must therefore now be stated before emitter code chooses it by convenience. The body already knows enough to say what must remain distinct when the first proof slice is preserved.

Current root preservation behavior remains lineage evidence, not automatic v1 law. The root line shows a historically real preservation path in which emitted artifact bodies, run occurrence, and preserved output remain tightly coupled. That evidence remains important. It does not settle the v1 preservation posture.

## 3. First Principle

Preservation preserves what already stands.

Preservation does not create, redefine, or silently merge artifact law.  
Body remains body.  
Envelope remains envelope.  
Preservation remains preservation.

In v1 terms, the registry must preserve the result of earlier lawful stages without rewriting those stages into one combined preserved object that hides what actually stood, what merely traveled together, and what belonged only to preservation context.

## 4. Preservation Scope of the First Proof Slice

The first ordinary proof slice is bounded to:

- validation artifact
- witness artifact
- governance action
- transition record
- state record

This is the ordinary preservation scope of the first v1 proof slice.

Continuity-turn is out of scope for this first ordinary preservation posture. Continuity remains a special case under the current v1 line and requires later handling consistent with the present v1 distinctions between body, envelope, and preservation.

## 5. Preservation Layers

The first v1 proof slice distinguishes the following preservation layers:

- canonical body preservation
- optional envelope-bearing preservation
- preservation or conformance reading material where relevant

Canonical body preservation preserves the canonical artifact body as canonical body.

Optional envelope-bearing preservation preserves the lawful case in which a canonical body traveled together with explicit envelope context while remaining separable from it.

Preservation or conformance reading material preserves what is needed so later reading can still tell whether body, envelope, and preservation each stood or failed at their own layer.

These layers may be preserved in relation. They must not be collapsed into one undifferentiated preserved thing.

## 6. Placement Posture

V1 preservation must keep body, envelope, and preservation or conformance results separately readable.

Preservation may group related outputs, but it must not collapse them into one undifferentiated preserved object. Preservation should support recovery of what stood at each earlier stage:

- what stood as canonical body
- what, if anything, traveled as envelope-bearing emission
- what was preserved as authoritative preservation context
- what conformance posture or fixture posture applied where relevant

This posture does not require final filename rules or final storage topology here. It requires only that the preserved result remain layer-readable rather than convenience-flattened.

## 7. Reading and Retrieval Posture

Preserved material must remain readable by layer.

Retrieval should not force the reader to confuse canonical body with envelope or preservation context. Preservation success does not override earlier body or envelope failure.

Refusal-path material may remain preserved lawfully without being misread as accidental incoherence. If refusal, non-conformance, or bounded failure was the lawful result at a specific stage, retrieval must preserve that reading rather than laundering it into generic preserved success.

## 8. Current-v0 / Desired-v1 Distinction

Current root registry and output posture remains historically real v0 lineage.

That root posture shows how the existing body preserved emitted artifacts under a run-saturated path. It remains important as source-side evidence.

This v1 registry posture is the target preservation posture that later emitter work must serve. This is not blame language. It is the explicit statement that v1 preservation is being re-derived rather than silently inherited from the root line’s convenience path.

## 9. Continuity Boundary

Continuity-turn remains outside this first ordinary preservation posture.

Later continuity handling must remain consistent with the current v1 distinctions between body, envelope, and preservation. This file must not silently absorb continuity into ordinary preservation by convenience.

The first ordinary preservation posture is for the five currently re-derived canonical body families only.

## 10. Anti-Collapse Rules

A conforming first v1 preservation posture must not allow:

- preservation-first definition of artifact
- combined preserved object that destroys body or envelope recoverability
- preservation context pretending to be canonical artifact body
- preserved refusal-path material misread as accidental drift
- continuity shortcut inside the first ordinary preservation posture

It must also not allow preserved grouping to erase which earlier stage or layer actually stood, failed, refused, or remained out of scope.

## 11. Downstream Consequences

Later emitter re-derivation must support this preservation posture.

Later fixture preservation must support this posture. Later transfer-account entries should remain readable through this posture where relevant.

This file is the registry and preservation bridge before concrete emitter work. It states the bounded preservation reading that later implementation surfaces must preserve rather than overwrite.

## 12. Closing Boundary Statement

This file defines bounded v1 registry and preservation posture only.

Later files or implementation work may realize this posture in emitter and preservation surfaces. This file exists so v1 can preserve the first proof slice without re-importing v0 collapse patterns.
