# IAMMAI v1

## 1. Purpose

This file is the first bounded entry surface for the `v1/` derivation line.

Its job is to explain what `v1/` is, what it is not, how it relates to the frozen root `v0` source-side body, and how to read the initial v1 law files now standing in this folder.

It does not redefine the law, settle runtime or schema design, or declare `v1/` a standing line by folder creation alone.

## 2. What `v1/` Is

`v1/` is a new admissible derivation line beside the frozen root `v0` source-side body.

It exists for explicit re-derivation where unstable downstream surfaces require it. Its purpose is not to restart the whole body, but to bring doctrine, schema, enforcement, fixture classes, and proof back into lawful relation where the root line showed drift or instability.

Within that work, `v1/` preserves the distinction between:

- inherited source-side authority
- source-side lineage and evidence
- re-derived v1 surfaces

## 3. What `v1/` Is Not

`v1/` is not:

- a constitutional restart
- a silent cleanup of `v0`
- a replacement of root by folder adjacency alone
- a standing line by default

## 4. Current Internal Law of `v1/`

The current internal law of `v1/` is carried by six files:

- `01_SEAM_DECLARATION.md`: defines the repo-scale seam between frozen root `v0` and the `v1/` line
- `02_AUTHORITY_AND_INHERITANCE_MAP.md`: defines what remains authoritative from source-side, what remains evidence only, and what classes require re-derivation
- `03_ARTIFACT_BOUNDARY_DECISION.md`: defines the first explicit boundary between canonical artifact body and execution or envelope context
- `04_FIXTURE_TAXONOMY.md`: defines the first explicit fixture classes so positive, refusal-path, illegibility, and broken materials do not collapse into one kind
- `05_STANDING_CRITERIA.md`: defines the bounded criteria by which `v1/` may later be recognized as standing
- `06_V0_TO_V1_TRANSFER_ACCOUNT.md`: defines the first bounded transfer account for what may cross from root `v0` into `v1/`

## 5. Reading Order

Read the current `v1/` law files in this order:

1. `01_SEAM_DECLARATION.md`
2. `02_AUTHORITY_AND_INHERITANCE_MAP.md`
3. `03_ARTIFACT_BOUNDARY_DECISION.md`
4. `04_FIXTURE_TAXONOMY.md`
5. `05_STANDING_CRITERIA.md`
6. `06_V0_TO_V1_TRANSFER_ACCOUNT.md`

## 6. Current Status

`v1/` is opened.

Its initial law files are standing in the sense that the seam, inheritance posture, artifact boundary, fixture taxonomy, standing criteria, and transfer account have now been explicitly articulated inside the new line.

Broader standing of `v1/` still depends on later re-derivation and fresh proof. Until that occurs, `v1/` remains an opened derivation line with explicit law already in place, not a completed downstream body.

## 7. Closing Orientation

`v1/` exists to re-derive what drifted without falsifying what held.
