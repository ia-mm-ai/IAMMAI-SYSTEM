# IAMMAI v1 Standing Criteria

## 1. Purpose

This file defines the first bounded criteria by which `v1/` may later be recognized as a standing admissible derivation line rather than merely an open folder and intention.

Its job is to state what class of closure must exist before `v1/` may be treated as standing.

It does not define:

- a constitutional rewrite
- a seam declaration
- an authority or inheritance map
- an artifact-boundary decision
- a fixture taxonomy
- a runtime contract
- a schema file
- a README
- a project-management checklist

It is a bounded standing-criteria note.

## 2. First Principle

`v1/` does not stand by creation alone.

Standing must follow explicit coherence.  
Standing must be earned through lawful re-derivation, not assumed through cleaner wording or better organization.

## 3. Why Standing Criteria Are Needed

Without explicit criteria, `v1/` can be mistaken as standing too early.

Early standing claims would recreate the same anti-collapse problems the repo is trying to prevent. A cleaner directory, sharper wording, or partial downstream restatement could begin to impersonate a standing line before law, artifact boundary, fixture handling, enforcement, and proof have actually closed coherently.

The criteria exist to bind recognition to actual closure.

## 4. Minimum Standing Conditions

At a minimum, `v1/` should not stand until the following class-level conditions hold:

- the seam is explicit
- inheritance posture is explicit
- artifact-boundary law is explicit
- fixture taxonomy is explicit
- schema and emitted artifact shape are no longer drifting in the same uncontrolled way
- enforcement surfaces are explicit enough to support clean proof
- fresh proof artifacts exist under the new line

These conditions are architectural. They do not require full system completion, but they do require enough lawful closure that `v1/` is no longer only an opened derivation space.

## 5. What Does Not Count As Standing

The following do not count as standing:

- opening a folder
- writing a README only
- cleaner descriptions without enforcement closure
- carrying over authority by assumption
- reusing `v0` proof as if it automatically proves `v1`

## 6. Proof and Evidentiary Force

Standing requires fresh proof under the new line.

Inherited source remains source-side authority. `v1/` must produce its own coherent emitted body where relevant. Fixture clarity and proof clarity must both be present so the new line can show what stands, what is only example, and what still fails boundedly under the new derivation posture.

## 7. Anti-Collapse Rules

The following must not occur:

- standing by adjacency
- standing by cleaner language alone
- standing by inheritance vibe
- standing by partial re-derivation while drift remains unresolved
- standing without explicit relation between law, schema, enforcement, and proof

## 8. Closing Boundary Statement

This file defines only the criteria by which `v1/` may later stand.

Later files and fresh proof may satisfy or fail these criteria. Until then, `v1/` remains opened but not self-authorized.
