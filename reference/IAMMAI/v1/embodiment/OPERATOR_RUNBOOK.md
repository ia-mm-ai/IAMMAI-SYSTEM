# IAMMAI v1 Operator Runbook

## 1. Purpose

This file defines the bounded operator-level runbook for the first controlled v1 proof slice that follows the current v1 runtime law and emission plan and precedes concrete emitter re-derivation.

Its job is to state how the first v1 proof slice is to be exercised and read at operator level, without becoming code, without pretending continuity is already settled, and without silently importing v0 run-saturated posture.

It does not define:

- a constitutional rewrite
- a seam declaration
- an authority or inheritance map
- an artifact-boundary decision
- a schema file
- an emitter implementation patch
- a validator code note
- a continuity redesign
- a storage topology design
- a project-management roadmap
- a README

It is a bounded operator runbook.

## 2. Why This Runbook Is Needed Now

V1 now has body schemas, conformance posture, runtime flow, and embodiment emission plan.

The first proof slice therefore needs an operator-level reading before emitter code is re-derived. The operator must know what is being exercised, in what order it is to be read, and what kinds of failure are lawful without flattening every result into one pass or fail impression.

Current root runners remain lineage evidence, not automatic v1 procedure. They show what the v0 line historically did, including run-saturated identity and continuity handling, but they do not by themselves define the operator posture of the v1 proof slice.

## 3. First Principle

The operator must exercise what has been lawfully formed.

Body comes before envelope.  
Envelope comes before preservation.  
Later carrying or preservation must not redefine earlier artifact standing.

The operator therefore reads the proof slice in the same order that the artifact is lawfully claimed. The operator does not begin from preservation, from combined travel, or from historical familiarity with the root runners.

## 4. Scope of the First Controlled Proof Slice

The first controlled proof slice is bounded to the currently re-derived canonical body families:

- validation artifact
- witness artifact
- governance action
- transition record
- state record

This first slice is intentionally small and decisive. It exists to show ordinary v1 artifact operation without re-collapsing body, envelope, and preservation.

Continuity-turn is out of scope for this first ordinary proof slice. Continuity remains a special case under the current v1 line and requires later handling consistent with current v1 law.

## 5. Operator Sequence

The bounded operator-level sequence is:

1. canonical body formation  
2. canonical body conformance  
3. optional envelope-bearing emission  
4. envelope-bearing conformance  
5. preservation placement  
6. preservation conformance  
7. fixture interpretation

This is the lawful order of reading.

The operator first asks whether canonical artifact body was formed as canonical body. The operator then asks whether that body conforms as canonical body. Only after that may the operator read any optional combined carrying posture. Only after that may the operator read preservation. Fixture meaning is read after the relevant stage has already been identified.

## 6. Positive Path

The positive lawful path is meant to demonstrate that the first ordinary v1 proof slice can:

- form canonical artifact bodies
- keep those bodies distinct from envelope context
- preserve explicit body or envelope separability where combined carrying exists
- preserve artifacts without allowing preservation to redefine them

This positive path should remain small and ordinary. It does not prove total v1 completion. It proves that stage order and layer distinction can hold in one bounded proof slice.

## 7. Negative and Refusal-Path Posture

The bounded negative or refusal-path example is meant to demonstrate that explicit bounded failure can remain lawful.

In this first proof slice, bounded failure may include body non-conformance, envelope non-conformance, preservation non-conformance, or a lawful refusal-path result where the exercised boundary is expected to hold by non-admission rather than by passage.

Refusal-path outcome is not the same as architectural incoherence. If the exercised boundary was intentionally constructed to refuse, then refusal may be the lawful result rather than evidence of collapse.

## 8. Reading Outcomes by Layer

The operator must read outcomes by layer:

- body outcome
- envelope outcome
- preservation outcome
- fixture interpretation outcome

Body outcome answers whether the canonical artifact body stands as canonical body.

Envelope outcome answers whether optional combined carrying preserved explicit body or envelope distinction.

Preservation outcome answers whether registry or preservation posture remained typed and non-redefining.

Fixture interpretation outcome answers what kind of example was exercised and whether its success, failure, or refusal was expected at that stage.

The operator must not flatten these into one undifferentiated success or failure judgment.

## 9. Stop Conditions

The operator must stop when canonical body does not stand.

The operator must stop when combined carrying breaks body or envelope distinction.

The operator must stop when preservation redefines artifact law rather than preserving what already stood.

The operator may record a lawful refusal-path result without treating it as architectural collapse when:

- the refusal was bounded and explicit
- the exercised stage or layer was the one expected to refuse
- the refusal did not silently blur body, envelope, or preservation distinction

Stopping is therefore stage-aware. Not every non-passage is collapse. But collapse at the exercised stage must stop the slice rather than being softened into atmosphere.

## 10. Current-v0 / Desired-v1 Distinction

Current root runs remain historically real v0 lineage.

They preserve what the root line actually emitted and preserved, including the fact that current artifact ids, artifact bodies, and continuity outputs remain tightly coupled to run occurrence.

This runbook defines the desired v1 operator posture that later emitter work must serve. This is not blame language toward the root line. It is the explicit statement that v1 proof execution is being read under newly articulated v1 law rather than under inherited v0 convenience.

## 11. Continuity Boundary

Continuity-turn remains outside this first ordinary proof slice.

Later continuity handling must remain consistent with current v1 law, especially the distinction between canonical body, envelope-bearing emission, and preservation context.

This runbook must not silently absorb continuity into ordinary artifact operation by convenience. The first ordinary slice is bounded to the five canonical body families already re-derived.

## 12. Anti-Collapse Rules

A conforming operator posture must not allow:

- envelope-first operator reading
- preservation-first reading of success
- combined output treated as if body standing were already settled
- flattening of stage-specific failure into total incoherence
- continuity shortcut inside the first ordinary proof slice

It must also not allow historically real root behavior to override v1 law merely because that earlier path already exists in the repository.

## 13. Downstream Consequences

Later emitter re-derivation must support this runbook.

Later fixture generation must support this runbook. Later transfer-account entries should be readable through this runbook where relevant.

This file is the embodiment bridge from plan into controlled proof execution. It states how the first proof slice is to be exercised and read before concrete emitter re-derivation begins.

## 14. Closing Boundary Statement

This file defines the bounded operator runbook only.

Later files or implementation work may realize this runbook in emitter surfaces. This runbook exists so v1 can enter controlled proof execution without re-importing v0 collapse patterns.
