# IAMMAI v1 Source Selection and Admissibility Posture

## 1. Purpose

This file defines the bounded v1 source-selection and source-admissibility posture for implementation-local proof-slice work that depends on preserved prior runs.

Its job is to state how v1 may lawfully select and use preserved ordinary proof-slice runs as canonical anchor sources and preserved continuity runs as predecessor sources without silently letting retrieval convenience, recency, or filesystem ordering become hidden protocol law.

It does not define:

- a constitutional rewrite
- a seam declaration
- an authority or inheritance map
- an artifact-boundary decision
- a schema file
- an emitter implementation patch
- a validator code note
- a storage topology design
- a project-management roadmap
- a generic README

It is a bounded runtime-law posture note.

## 2. Why This File Is Needed Now

V1 now has multiple preserved runs under `v1/registry/runs/`.

The ordinary proof-slice line now preserves at least one lawful ordinary run, and the continuity line now preserves more than one bounded continuity run. Continuity work therefore no longer depends on only one atmospheric prior source. It now depends on selecting preserved ordinary and continuity sources from a growing preserved body.

Source selection must therefore be stated before convenience hardens into hidden law. Without an explicit posture, directory presence, recency, or retrieval ease can begin to impersonate source admissibility even where the lawful relation is actually narrower and more explicit.

## 3. First Principle

Only admissible preserved sources may be used as sources.

Selection convenience does not create source authority.  
Selection must preserve lawful relation, not just availability.

In v1 terms, a preserved run is not admitted as source merely because it exists on disk. A source must be admissible for the class of relation being claimed, and the later use must remain readable as relation rather than as accidental retrieval habit.

## 4. Source Classes

This posture distinguishes two bounded source classes:

- ordinary anchor source
- continuity predecessor source

An ordinary anchor source is a preserved ordinary proof-slice run used to supply canonical artifact anchoring for continuity work. Its job is to keep continuity subordinate to preserved canonical ordinary reality rather than to generic sequence or generic history.

A continuity predecessor source is a preserved positive continuity run used to supply lawful predecessor succession for a later continuity turn. Its job is to preserve append-oriented continuity across continuity turns where such succession is part of lawful continuity standing.

These classes must remain distinct. The ordinary anchor source supplies canonical artifact anchoring. The continuity predecessor source supplies predecessor succession. One must not silently stand in for the other.

## 5. Ordinary Anchor Source Admissibility

A preserved ordinary run is admissible as a canonical anchor source only where it remains readable as a lawful ordinary proof-slice result.

At bounded posture level, admissibility for an ordinary anchor source requires:

- readable preserved canonical body outputs for the relevant ordinary artifact families
- readable positive body-conformance outcomes for the canonical bodies being used as anchors
- readable layer outcomes showing that body, optional envelope-bearing emission, and preservation remained distinguishable
- readable matter relation sufficient for later continuity work to preserve matter coherence where that relation is required

Mere directory presence is not enough. Mere file presence is not enough. A run is not admitted as ordinary anchor source merely because a `canonical_bodies/` directory exists.

Bounded negative fixture material inside the same preserved run does not by itself disqualify the run. The key question is whether the preserved ordinary positive path remains readable and admissible as positive ordinary standing at the layers relevant to anchoring.

## 6. Continuity Predecessor Source Admissibility

A preserved continuity run is admissible as a predecessor source only where it remains readable as positively standing continuity rather than merely as a preserved continuity-shaped directory.

At bounded posture level, admissibility for a continuity predecessor source requires:

- a readable preserved positive continuity body
- a readable positive continuity-body conformance outcome for that body
- readable continuity layer outcomes showing that continuity body, any explicit execution relation, and preservation remained distinguishable
- a readable retained relation to canonical artifact anchoring rather than predecessor succession alone
- matter coherence sufficient for the later continuity use being claimed

The predecessor source must itself be positively standing continuity. It is not enough that a continuity directory exists, that a continuity body file exists, or that negative fixture material exists beside it.

Bounded negative fixture material inside the same preserved continuity run does not by itself disqualify the run. The key question is whether the preserved positive continuity path stands readably as lawful continuity.

Predecessor succession must also remain subordinate to canonical artifact anchoring. A predecessor source is inadmissible if its later use would sever predecessor succession from the anchor relation on which lawful continuity still depends.

## 7. Matter and Relation Coherence

Source selection must preserve lawful matter coherence where relevant.

If a continuity turn is being formed in relation to preserved ordinary canonical reality, the selected ordinary anchor source and the selected continuity predecessor source must remain relation-coherent rather than merely co-located in the registry tree.

Continuity predecessor selection must not silently drift away from the canonical anchor relation it depends on. If a predecessor source was itself anchored to one preserved ordinary line, later successor selection must not treat that predecessor as freely portable across incompatible anchor relations merely because the filesystem makes both directories easy to retrieve.

Source compatibility must therefore be read as relation, not as filename coincidence, directory similarity, or naming resemblance.

## 8. Selection Posture

Implementation-local default selection by recency, latest suitable preserved source, or comparable bounded convenience may be acceptable for local runners.

That is acceptable only where all of the following remain true:

- the selected source is already admissible
- the selected source is recorded explicitly once chosen
- the local default is not mistaken for protocol law

Selection convenience may therefore act as a bounded local default among admissible candidates. It must not create admissibility, and it must not silently define source authority.

If later explicit selection is introduced, that still would not override admissibility law. Explicit choice must still obey source class, admissibility, matter coherence, and recording posture.

No source may be chosen merely because it is easiest to retrieve.

## 9. Source Recording Posture

Whenever a source is selected and used, that selection must be recorded explicitly.

Anchor source notes and predecessor source notes are lawful examples of this posture under the current bounded runners. They preserve explicit visibility into what source was selected, what class of source it was, and how later continuity work depended on it.

Source recording must preserve enough information to reconstruct what was selected and why. At bounded posture level, that means later readers should be able to recover:

- the selected preserved run
- the selected preserved continuity directory where relevant
- the selected positive body or summary material where relevant
- the relation class being preserved
- the matter or anchor relation needed to read the selection lawfully

Recorded selection is therefore part of admissible use, not an optional convenience note after the fact.

## 10. Current-v0 / Desired-v1 Distinction

Current root behavior remains historically real v0 lineage.

That root line remains important as source-side evidence of how the earlier body actually formed, emitted, and preserved relation under a more run-centric posture. It does not automatically settle how v1 should select preserved sources once multiple bounded v1 runs exist beside one another.

V1 source selection posture must therefore be explicit rather than silently inherited from convenience. This is not blame language. It is the explicit statement that selection habit, retrieval habit, and directory habit must not become hidden law merely because the repository now contains more than one preserved candidate source.

## 11. Anti-Collapse Rules

A conforming v1 source-selection posture must not allow:

- retrieval convenience standing in for source authority
- predecessor source admitted without lawful continuity standing
- predecessor succession replacing canonical artifact anchoring
- filesystem presence treated as admissibility
- unrecorded source selection in bounded proof-slice work
- recency default treated as protocol law

It must also not allow positive and negative material inside one preserved run to be read indiscriminately. Source admissibility must still be read through the lawful positive standing of the source class being used.

## 12. Downstream Consequences

Later runners must follow this source-selection posture.

Later preservation and retrieval handling must remain readable through this posture. Later implementation may refine selection mechanics, but it must not violate admissibility law, matter coherence, anchor discipline, or source-recording posture.

This file is the cross-cutting bridge before more proof-slice variation or broader implementation. It constrains later runner work so additional local proof does not quietly turn source convenience into hidden law.

## 13. Closing Boundary Statement

This file defines bounded v1 source-selection and source-admissibility posture only.

Later files or implementation work may realize this posture in runner and preservation surfaces. This file exists so v1 can continue implementation without letting source convenience silently become law.
