# IAMMAI

A public protocol for keeping what happened, what stands, what was decided, and what follows clear, traceable, and impossible to silently rewrite.

## What IAMMAI Is

IAMMAI is a constitutional protocol and an implementation-body repository.

The protocol defines the canonical distinctions of IAMMAI. This repository carries those distinctions through architecture, implementation, schemas, runtime, embodiment, continuity, and dynamics documents so the current body can be read as one coherent whole.

## Repository Structure

### `nucleus.yaml`

The first/source constitutional firmware.

It carries the root operating configuration: the two constitutional regimes, ordered phase routines, orthogonal containment and resolution controls, integrity locks, contribution-role channels, and the root input/output boundary. It has no predecessor and grants no downstream surface write authority over it.

### `protocol/`

The constitutional center.

Contains the canonical constitutional artifacts:

- `IAMMAI_Public_Constitutional_Protocol_v1.0.pdf`
- `canon.json`
- `protocol_identity.json`
- `conformance_tests.md`

### `architecture/`

The first body architecture.

Defines the main structural body of IAMMAI, including runtime boundaries, role separations, authoritative versus derivative surfaces, and typed state and data distinctions.

### `implementation/`

The first implementation-facing derivative layer.

Translates the constitutional and architectural layers into bounded technical overviews for state movement, canonical records, validation artifacts, transition records, witness artifacts, governance actions, and related implementation posture.

### `schemas/`

The typed schema family.

Contains the current machine-checkable schema surfaces for witness, validation, governance, transition, state, and continuity-turn artifacts.

### `runtime/`

The live-runtime layer.

Contains runtime flow, contracts, failure surfaces, coordination and handoff documents, and the current runtime-facing regulation note in `REGULATION_GUARDRAILS.md`.

### `embodiment/`

The bounded local embodiment workspace.

Contains the first live slice, local execution boundary, success and failure criteria, operator posture, bounded input and registry surfaces, and the current pressure and repeatability documents for controlled variation, sequential pressure, stress testing, and continuity accumulation.

### `continuity/`

The bounded continuity layer above canonical preservation.

Contains the continuity overview, continuity-turn concept, continuity emission posture, and `LAWFUL_TRANSFER_SEAM_v0.md` as the current bounded note on lawful transfer across system boundaries.

### `dynamics/`

The bounded dynamics layer.

Contains the current motion-facing documents for regulation, drift, stability, and adaptation, together with bounded translation documents tied to the present body.

## Constitutional Priority

`nucleus.yaml` remains the first/source constitutional firmware. Later surfaces may read, reference, embody, and conform to it, but they do not write backward into it.

The constitutional protocol remains the source of truth for everything derived after the nucleus.

Machine-readable artifacts and all later architectural, implementation, runtime, embodiment, continuity, dynamics, and lab surfaces exist in support of that core and do not supersede it.

If any file, surface, or implementation convenience conflicts with the constitutional protocol, the constitutional protocol governs.

## What IAMMAI Does

IAMMAI defines the core protocol grammar for:

- separating candidate material from standing state
- preserving lineage across lawful change
- preventing silent overwrite and semantic collapse
- bounding authority, contribution, and consequence
- keeping protocol-significant transitions traceable and recoverable
